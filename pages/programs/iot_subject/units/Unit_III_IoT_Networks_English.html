IoT Networks

Introduction to IoT Networks

An IoT network is a communication system that connects Internet of Things (IoT) devices, sensors, actuators, gateways, cloud servers and applications so that they can exchange data. A device becomes more useful when it can share the information it collects and receive commands from other systems.

The main purpose of an IoT network is to move information from the physical environment to digital systems and, when required, convert a digital decision into a physical action. For example, a soil-moisture sensor sends readings through a controller and network to a cloud service, where a mobile application can display the field condition to a farmer.

Need for an IoT Network

  • Connect devices to local networks, the internet or cloud platforms.
  • Transfer sensor readings to remote servers.
  • Enable monitoring through mobile applications and web dashboards.
  • Support remote control, alerts and automation.
  • Allow multiple devices to work together as one system.

Basic Working

Sensor → Microcontroller → Gateway / Router → Internet → Cloud → Application → User
Real-Life Example:
A smart home connects door sensors, cameras, bulbs and thermostats through a home network so that users can view their status and control them from an application.
Remember:
An IoT network provides the communication path through which devices exchange information with other devices, services and users.

Components of Basic IoT Networks

A basic IoT network consists of several components. Each component has a specific responsibility: sensors collect data, a controller processes it, network equipment forwards it, cloud services store or analyse it, and an application presents useful information to the user.

Component Relationship

A sensor needs a controller or another processing system to interpret its readings. Remote monitoring requires a communication path, while a cloud service or application needs device data to provide useful results. These components therefore work together as a connected system.

Remember:
Devices, sensors, controllers, gateways, networks, cloud services and applications combine to form an IoT system.

IoT Gateway and Router

An IoT gateway connects local IoT devices or networks with other networks, applications or cloud platforms. Some low-power devices use technologies such as Zigbee, Bluetooth or other specialised protocols and may not connect directly to the internet. A gateway can collect their data and forward it through an IP network.

A router forwards packets between networks according to network addressing and routing information. In a home, a Wi-Fi router commonly connects local devices to one another and provides access to the internet.

Gateway Functions

  • Collect data from local IoT devices.
  • Translate or bridge between supported communication protocols.
  • Filter, combine or format data before forwarding it.
  • Forward information to a server or cloud platform.
  • Support authentication, security policies and device management.
  • Perform local processing or edge computing when supported.

Gateway vs Router

Basis IoT Gateway Router

Protocol Support May bridge different device protocols. Primarily routes network-layer traffic.
Additional Work May filter data, manage devices or process data locally. May provide Wi-Fi, firewall and network address translation features.
Example Zigbee-to-IP gateway. Home Wi-Fi router.
Remember:

IoT Network Layers

An IoT network can be understood by dividing it into layers. Each layer performs a group of related tasks. Layered models help engineers organise a complex system, although the exact number and names of layers can vary between IoT architectures.

Common IoT Layers

Layer Responsibility Example
Perception / Device Layer Interacts with the physical environment and collects measurements. Sensors, RFID tags, cameras and actuators.
Network / Connectivity Layer Transfers data between devices, gateways and services. Wi-Fi, Ethernet, Bluetooth, Zigbee and IP.
Processing / Middleware Layer Stores, filters, processes and manages data or devices. Edge computer, IoT platform and cloud database.
Application Layer Provides services and information to end users. Smart farming dashboard or home-automation app.

Layer Example

In a smart parking system, an ultrasonic sensor detects whether a parking space is occupied. Wi-Fi or LoRaWAN carries the reading, a server processes the information, and a parking application displays available spaces to drivers.

Note:
Layer models are conceptual tools. Real products may combine functions from several layers in one device.

Wired IoT Connections

Wired IoT connections use physical cables to carry data between devices. They are suitable for fixed installations where cable routing is practical and a stable connection is required.

Ethernet

Ethernet is a widely used technology for wired Local Area Networks (LANs). It provides network communication through copper or fibre-optic cabling. It is useful in industrial systems, servers, gateways and smart buildings where dependable connectivity is needed.

USB

Universal Serial Bus (USB) is commonly used to connect a development board to a computer for programming, serial communication and, where supported, power. For example, many Arduino boards can be programmed through a USB connection.

Serial Communication Cable

Serial links transfer data one bit at a time. UART is a common asynchronous serial interface between microcontrollers and modules. Its TX and RX signal lines are usually crossed between two devices, and a common ground is required when the interface design calls for it.

Advantages

  • Stable and predictable connection in a properly installed system.
  • Less affected by radio-frequency interference than wireless links.
  • Can support high data rates, particularly with Ethernet or fibre.
  • Physical access to the cable can make network control easier in some installations.

Limitations

  • Cable installation can increase time and cost.
  • Mobility is limited by cable length and routing.
  • Long cable runs may require repeaters or specialised equipment.
  • Cables and connectors can be damaged physically.

Wireless IoT Connections

Wireless connections are widely used in IoT because devices may be installed in remote, mobile or difficult-to-wire locations. Wireless technologies differ in range, data rate, power consumption, network capacity and topology.

Common Wireless Technologies

Technology Typical Characteristics Example Use
Wi-Fi Relatively high data rate and common IP connectivity; often higher power use than low-power sensor links. Home devices, cameras and ESP boards.
Bluetooth / BLE Short-range communication; BLE is designed for low-power devices. Wearables, phone accessories and local control.
Zigbee Low-power mesh networking for suitable devices. Smart-home sensors and lighting.
LoRaWAN Long-range, low-power communication with a low data rate. Agriculture and remote monitoring.

Wi-Fi

Wi-Fi connects devices to a wireless local area network and can provide access to local services or the internet. ESP8266 and ESP32 boards are commonly used in Wi-Fi-based IoT prototypes.

Bluetooth

Bluetooth supports short-range wireless communication. Bluetooth Low Energy (BLE) is designed for devices that need to exchange small amounts of data while conserving battery power. It is common in wearables and phone-controlled devices.

Zigbee

Zigbee is a low-power wireless technology that can support mesh networking. Mesh-capable devices can relay messages through other network nodes, helping cover a larger area in suitable deployments.

LoRaWAN

LoRaWAN is a Low Power Wide Area Network (LPWAN) protocol designed for long-range communication with low-power end devices. It is useful for sending small amounts of data from remote locations, such as farms and environmental monitoring sites.

TCP and UDP

TCP and UDP are transport-layer protocols. They provide different ways for applications to exchange data across IP networks. The choice depends on whether the application prioritises reliable, ordered delivery or lower overhead and timely delivery.

TCP

Transmission Control Protocol (TCP) is connection-oriented. It establishes a connection before data transfer and provides mechanisms for reliable, ordered delivery, error detection and retransmission of missing data. These mechanisms add overhead, but are useful when complete and correctly ordered data is important. HTTP and many MQTT deployments use TCP.

UDP

User Datagram Protocol (UDP) is connectionless and has a smaller transport overhead. It does not guarantee delivery, ordering or retransmission. Applications may use UDP when low latency or simplicity is important and can handle any required reliability themselves. CoAP commonly uses UDP.

Basis TCP UDP
Connection Connection-oriented Connectionless
Delivery Reliable and ordered delivery mechanisms No delivery or ordering guarantee
Overhead Higher Lower
Common IoT Use HTTP and MQTT communication CoAP and time-sensitive datagrams

HTTP

HTTP request-response model पर based है। Device server को request send करता है और server response देता है। REST API में HTTP बहुत common है, लेकिन low-power IoT devices के लिए यह heavier हो सकता है।

CoAP constrained devices के लिए lightweight protocol है। यह UDP पर based है और HTTP जैसा resource model follow करता है।

DNS and DHCP

DNS and DHCP are supporting services used in IP networks. DNS helps devices find the IP address associated with a domain name. DHCP automatically provides network configuration to devices joining a network.

DNS

Domain Name System (DNS) translates domain names into IP addresses. For example, when an IoT device needs to contact a cloud service using a host name, it can query DNS to discover the address to which it should connect.

DHCP

Dynamic Host Configuration Protocol (DHCP) automatically assigns IP configuration to devices. A DHCP server can provide an IP address, subnet mask, default gateway and DNS server information. A home router commonly provides DHCP service to devices on the local network.

Basis DNS DHCP
Full Form Domain Name System Dynamic Host Configuration Protocol

Benefit Users and devices can use names instead of remembering IP addresses. Reduces manual network configuration.

Basic Understanding of Microcontrollers

A microcontroller is a compact integrated circuit that contains a processor, memory and input/output peripherals. It is designed to control a specific embedded application. In an IoT device, a microcontroller can read sensors, execute program logic, control outputs and communicate with other devices.

Main Parts

  • CPU: Executes instructions and controls operations.
  • Flash / Program Memory: Stores the program.
  • RAM: Stores temporary data while the program runs.
  • GPIO Pins: Connect digital input and output devices.
  • Timers and Counters: Support timing and event counting.
  • ADC: Converts analog input voltage into digital values, when available.
  • Communication Interfaces: May include UART, SPI, I²C, USB, Wi-Fi or Bluetooth, depending on the chip.

Why Microcontrollers Are Important in IoT

  • Read information from sensors.
  • Process data and execute automation rules.
  • Control actuators through suitable driver circuits.
  • Communicate with gateways, networks and other modules.
  • Support compact, low-power embedded devices.

GPIO, ADC and PWM

Microcontroller pins support different types of signals. GPIO, ADC and PWM are important concepts when connecting sensors and actuators to an IoT development board.

GPIO

General Purpose Input/Output (GPIO) pins can be configured as digital inputs or outputs. A button connected to an input pin and an LED controlled by an output pin are simple examples. Check the board documentation for voltage limits and pin restrictions.

ADC

An Analog-to-Digital Converter (ADC) converts an analog voltage into a digital number that a microcontroller can process. This is useful when reading analog sensors such as a voltage-divider LDR circuit. The resolution and input voltage range depend on the board.

PWM

Pulse Width Modulation (PWM) controls the average power delivered to a load by switching a signal rapidly and changing its duty cycle. It is commonly used for LED brightness and, with a suitable driver, motor-speed control. PWM is not the same as a true analog voltage output.

// Examples for compatible Arduino boards
digitalWrite(13, HIGH); // Set a digital output HIGH
int value = analogRead(A0); // Read an analog input
analogWrite(9, 128); // PWM-style output on supported boards
Important:
Pin capabilities and function names vary between Arduino-compatible boards. Always check the board's documentation.

Practical IoT Communication Flow

Practical communication flows show how an IoT device collects information, processes it and exchanges data with another device or service. The communication method depends on the project requirements and the hardware available.

Example 1: Sensor to Cloud

DHT11 / DHT22 Sensor
        ↓
      ESP32
        ↓
       Wi-Fi
        ↓
   MQTT or HTTP
        ↓
    Cloud Service
        ↓
   Mobile Application

The sensor measures temperature and humidity. The ESP32 reads the values and sends them over Wi-Fi using an application protocol such as MQTT or HTTP. A cloud service stores or displays the data, and the user views it through an application.

Example 2: Bluetooth Control

Mobile Application
        ↓
     Bluetooth
        ↓
   Arduino / ESP32
        ↓
 Driver / Relay Module
        ↓
      Bulb / Fan

A mobile application sends a command over Bluetooth. The controller receives the command and operates a suitable driver or relay circuit to switch a load. Mains-powered equipment must be handled using correctly rated, enclosed and safely installed hardware.

Example 3: Local Display

Sensor → Arduino → I²C LCD / OLED Display

The controller reads a sensor and displays the result locally. Internet connectivity is not required for this basic arrangement.

Complete Flow Explanation

  1. A sensor collects data from the physical environment.
  2. The microcontroller reads and processes the measurement.
  3. A communication interface and protocol transfer the data when required.
  4. A gateway or cloud service receives and may store or analyse the information.
  5. An application displays readings, alerts or device status to the user.
  6. A user or automatic rule may send a command back to the controller, which operates an actuator.
Remember:
A complete IoT solution combines sensing, processing, communication, application services and (where needed) actuation.
