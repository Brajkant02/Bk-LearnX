1. IoT Architecture का परिचय

IoT Architecture वह structured design है जो IoT system के अलग-अलग elements—जैसे sensors, actuators, protocols, cloud services और layers—को एक networking system में व्यवस्थित करता है।

IoT architecture की structure उसकी functionality और अलग-अलग sectors में उसके implementation पर depend करती है। इसलिए हर IoT deployment में architecture बिल्कुल एक जैसी होना आवश्यक नहीं है।

Exam Definition: IoT Architecture is a system of numerous elements such as sensors, actuators, protocols, cloud services and layers that together make up an IoT networking system.

2. IoT Architecture के प्रमुख Elements

Sensors

Environment या physical condition से data collect करते हैं।

Actuators

Received instructions के आधार पर physical action perform करते हैं।

Protocols

Devices और systems के बीच communication के rules provide करते हैं।

Cloud Services

Data processing, storage और application-level services provide कर सकती हैं।

Layers

पूरे IoT system को functional responsibilities के अनुसार organize करती हैं।

3. Resource Model and Abstraction

Resource model IoT system में available resources और उनके representation को समझने का तरीका है। IoT devices के resources में sensing, actuation, communication, processing, memory और energy जैसी capabilities शामिल हो सकती हैं।

Abstraction का उद्देश्य lower-level device details को एक understandable representation के रूप में expose करना है, ताकि applications को hardware की internal complexity सीधे handle न करनी पड़े।

Physical Device → Resource Representation → Communication Interface → Application
Concept: Resource abstraction IoT devices की capabilities को higher-level software/application के लिए manageable बनाती है।

4. 3-Layer IoT Architecture

3-layer architecture IoT architecture का एक basic model है। इसमें system को तीन major layers में divide किया जाता है:

LayerMain Work
Perception LayerPhysical world से sensing और data collection.
Network LayerCollected data को communication/network के माध्यम से आगे transfer करना.
Application LayerUser/application-specific services provide करना.
Perception → Network → Application

Working: Sensor physical environment से data collect करता है → Network layer data transfer करती है → Application layer उस data को required service/use-case में apply करती है।

5. 4-Layer IoT Architecture

4-layer model IoT system की processing और support responsibilities को अधिक clearly separate करता है। एक commonly used representation में:

LayerRole
Perception LayerSensors/actuators और physical data interaction.
Transport / Network LayerData को devices, gateways और processing systems के बीच transfer करना.
Processing / Middleware LayerData processing, storage, service management और middleware functions.
Application LayerEnd-user/application-specific IoT services.
Perception → Transport/Network → Processing/Middleware → Application
4-layer architecture में layer naming/reference अलग-अलग textbooks या implementations में थोड़ी बदल सकती है; syllabus के context में layers की functional responsibility को समझना मुख्य है।

6. 5-Layer IoT Architecture

5-layer architecture IoT system को अधिक detailed functional structure में divide करती है। A commonly used model में ये layers होती हैं:

Perception Layer

Physical objects/environment से data sensing.

Transport Layer

Data को perception से processing system तक transport करना.

Processing Layer

Data processing, storage और analysis.

Application Layer

Specific IoT services और applications.

Business Layer

Overall business logic, management और decision-level view.

Perception → Transport → Processing → Application → Business

7. Types of IoT Layers — Overview

दिए गए syllabus के अनुसार IoT system में निम्न functional layers महत्वपूर्ण हैं:

Perception Layer

Sensing और physical-world interaction.

Connectivity Layer

Devices और networks के बीच connectivity/communication.

Edge Layer

Data source के पास local processing और quick response.

Processing Layer

Data processing, storage और analytics.

Application Layer

User-facing IoT services.

Business Layer

Business-level management, policies और decisions.

Security Layer

System, communication और data की protection.

8. Perception Layer

Perception Layer IoT architecture की physical-world interaction layer है। यह sensors और related devices के माध्यम से environment से information collect करती है।

  • Temperature, humidity, light, motion आदि जैसी conditions को sense करना.
  • Sensor-generated signals/data को आगे system में भेजने के लिए तैयार करना.
  • Actuators के माध्यम से physical action से interaction भी architecture का हिस्सा हो सकता है.
Example: Smart agriculture में soil moisture sensor soil की moisture condition detect करता है।

9. Connectivity Layer

Connectivity Layer IoT devices, gateways और अन्य system components के बीच communication/connectivity provide करती है।

  • Data transmission के लिए communication links का उपयोग.
  • Devices को network से connect करना.
  • Collected data को आगे edge/cloud/processing systems तक पहुंचाना.
Device → Connectivity → Gateway/Network → Processing

10. Edge Layer

Edge Layer data source के comparatively पास processing capabilities provide करती है। इसका उद्देश्य हर piece of data को दूर स्थित central/cloud system तक भेजने की आवश्यकता को कम करना हो सकता है।

  • Local/near-device processing
  • Quick response के लिए useful
  • Selected data को आगे processing/cloud services तक भेजना
  • IoT devices और higher-level systems के बीच intermediate role

11. Processing Layer

Processing Layer collected IoT data को process, store और analyze करने के लिए responsible functional layer है। इसमें centralized processing, storage और analytics services शामिल हो सकती हैं।

  • Data processing
  • Data storage
  • Data analysis
  • Services के लिए processed information तैयार करना

12. Application Layer

Application Layer IoT data और system capabilities को specific user/application services में बदलती है।

Smart Home

Home monitoring और automation.

Healthcare

Connected monitoring services.

Industry

Equipment monitoring और automation.

Agriculture

Environment/crop-related monitoring.

13. Business Layer

Business Layer IoT system के overall business view, management, policies और decision-making को represent करती है।

  • Business requirements के अनुसार IoT system का evaluation.
  • Policies और management decisions.
  • IoT services के performance/overall operation का higher-level view.

14. Security Layer

Security Layer IoT architecture की एक मुख्य आवश्यकता है क्योंकि IoT systems large numbers of connected devices, networks और data के साथ operate कर सकते हैं।

Syllabus के अनुसार प्रमुख challenges में data breach, tracking malicious software और hacking शामिल हैं।

ChallengeMeaning
Data BreachUnauthorized access के कारण data का exposure या theft.
Malicious SoftwareHarmful software का IoT environment में प्रवेश/प्रभाव.
HackingUnauthorized access या system control प्राप्त करने का प्रयास.
Security focus: IoT architecture में devices, communication, data और services की protection को architecture के साथ integrate करना आवश्यक है।

15. IoT Design Principles

IoT system design करते समय architecture को functional requirements और deployment environment के अनुसार organize करना चाहिए। प्रमुख design principles:

Interoperability

Different devices/systems के बीच effective communication.

Scalability

Devices और data volume बढ़ने पर system का support.

Security

Devices, communication और data की protection.

Reliability

Consistent और dependable operation.

Modularity

Architecture को manageable functional components में divide करना.

Efficiency

Limited device resources और network resources का appropriate use.

16. IoT Devices

IoT Devices वे connected physical devices हैं जो sensing, actuation, communication या processing जैसी capabilities provide कर सकते हैं।

  • Sensors — physical/environmental data collect करते हैं.
  • Actuators — commands के अनुसार physical action perform करते हैं.
  • Gateways — devices और wider networks/services के बीच bridge की तरह काम कर सकते हैं.
  • Edge devices — source के पास processing support दे सकते हैं.
Device design considerations: power/resource limitations, connectivity, security, processing capability और deployment environment को ध्यान में रखना चाहिए।

17. IoT Deployment Models

IoT deployment model यह बताता है कि devices, processing और services को system में कहाँ और किस arrangement में deploy किया जाता है।

Model / ArrangementBasic Idea
Device-centricProcessing और functionality का बड़ा भाग device side पर.
Edge-orientedData source के पास edge nodes/gateways पर processing.
Cloud-orientedCentral/cloud services में storage, processing और analytics.
HybridDevice + Edge + Cloud capabilities का combination.
Devices → Edge/Gateway → Cloud/Processing → Applications

18. IoTivity — Open Source IoT Stack

IoTivity एक open-source IoT stack है। इसका उद्देश्य connected IoT devices और applications के बीच interoperability और communication को support करने वाले software components provide करना है।

IoTivity को समझते समय मुख्य idea यह है कि IoT ecosystem में अलग-अलग devices और applications को common communication/interoperability framework के माध्यम से काम करने में मदद मिले।

Exam Point: IoTivity = Open Source IoT Stack.

19. Complete IoT Architecture Working

Physical World → Perception → Connectivity → Edge → Processing/Cloud → Application → Business
↕
Security Across the Architecture

Step 1: Sensors physical environment से data collect करते हैं।

Step 2: Connectivity layer communication के माध्यम से data को आगे transfer करती है।

Step 3: Edge layer जरूरत के अनुसार data को source के पास process कर सकती है।

Step 4: Processing layer data को process, store और analyze करती है।

Step 5: Application layer processed information को user/service के रूप में प्रस्तुत करती है।

Step 6: Business layer overall management और decision-level view provide करती है।

Step 7: Security पूरे architecture में devices, data, communication और services को protect करने की आवश्यकता रखती है।

20. 3-Layer vs 4-Layer vs 5-Layer Architecture

ArchitectureLayersMain Focus
3-LayerPerception, Network, ApplicationBasic sensing → communication → application flow.
4-LayerPerception, Transport/Network, Processing/Middleware, ApplicationProcessing/middleware को अलग functional layer के रूप में दिखाना.
5-LayerPerception, Transport, Processing, Application, BusinessMore detailed architecture और business-level management.
Remember: अलग books/implementations में layer names और boundaries vary कर सकती हैं। Exam में अपने prescribed syllabus/textbook की terminology को priority दें।
