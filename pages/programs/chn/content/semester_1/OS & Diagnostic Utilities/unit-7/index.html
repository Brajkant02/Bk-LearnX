1. Backup क्या है?

Backup किसी महत्वपूर्ण data की अतिरिक्त copy बनाने की प्रक्रिया है, ताकि original data खो जाने, corrupt होने, accidentally delete होने, hardware failure, malware या किसी अन्य disaster की स्थिति में data को restore किया जा सके। Backup केवल copy बनाना नहीं है; एक useful backup strategy में backup की location, frequency, retention और restore testing भी महत्वपूर्ण होते हैं।

Exam Definition: Backup वह प्रक्रिया है जिसमें महत्वपूर्ण files, databases, configurations या अन्य digital data की सुरक्षित अतिरिक्त copy बनाई जाती है, ताकि आवश्यकता पड़ने पर उसे restore किया जा सके।

Backup की आवश्यकता

  • Accidental file deletion से recovery के लिए।
  • Hard disk/SSD failure की स्थिति में data बचाने के लिए।
  • Operating system या software failure के बाद recovery में सहायता के लिए।
  • Malware/ransomware जैसी घटनाओं के प्रभाव को कम करने के लिए।
  • Important documents और business data की continuity बनाए रखने के लिए।

2. Backup & Restore Procedures

Backup Procedure

Backup procedure में पहले identify किया जाता है कि कौन-सा data महत्वपूर्ण है, फिर suitable backup method और destination चुना जाता है। Backup complete होने के बाद उसकी integrity verify करना और recovery के लिए उपलब्ध रखना आवश्यक है।

Step 1: Important files, folders, databases और configurations identify करें।
Step 2: Backup frequency तय करें—जैसे daily, weekly या आवश्यकता के अनुसार।
Step 3: Backup type चुनें—Full, Incremental या Differential आदि।
Step 4: Suitable backup media/location चुनें।
Step 5: Backup execute करें।
Step 6: Backup completion और files की availability/integrity verify करें।
Step 7: Backup को सुरक्षित और, जहाँ संभव हो, original system से अलग location पर रखें।

Restore Procedure

Restore backup copy से data को वापस usable location या system में लाने की प्रक्रिया है। Restore करते समय correct backup version और destination चुनना जरूरी है।

Step 1: Data loss/failure का कारण identify करें और recovery environment तैयार करें।
Step 2: Required backup set और restore point identify करें।
Step 3: Backup data को verify करें।
Step 4: Files/system data को selected destination पर restore करें।
Step 5: Restored data की correctness और usability check करें।
Step 6: System को normal operation में वापस लाएँ और backup strategy review करें।
Important: Backup बना होना पर्याप्त नहीं है। Restore process को समय-समय पर test करना चाहिए, क्योंकि unusable या corrupted backup disaster के समय काम नहीं आएगा।

3. Types of Backup

Backup Typeक्या backup होता है?AdvantagesLimitations
Full BackupSelected data की पूरी copy।Restore comparatively simple और complete set available।अधिक storage और time लग सकता है।
Incremental BackupLast backup के बाद बदला/नया data।कम storage और faster backup।Full restore में multiple backup sets की आवश्यकता हो सकती है।
Differential BackupLast full backup के बाद बदला/नया data।Restore में सामान्यतः full + latest differential set चाहिए।समय के साथ differential size बढ़ सकता है।
Mirror BackupSource का mirror-like copy structure।Current data की accessible duplicate copy।Deleted/corrupted changes भी mirror में reflect हो सकते हैं यदि versioning न हो।

Full

Example: रविवार को पूरा 100 GB data backup।

Incremental

Monday को केवल Monday के बाद बदला data, फिर Tuesday को Monday backup के बाद नया बदला data।

Differential

Monday full के बाद Tuesday का accumulated changed data, फिर Wednesday को Monday full के बाद हुए सभी changes।

Best Practice

Critical data के लिए backup schedule और retention policy पहले से define करना चाहिए।

4. Media for Backup

Backup media वह storage medium है जिसमें backup data रखा जाता है। Media का चयन data size, cost, speed, portability, durability और recovery requirements के अनुसार किया जाता है।

Mediaमुख्य उपयोगAdvantages
External HDD/SSDPersonal और organizational backupsConvenient, reusable और comparatively high capacity।
USB Flash DriveSmall/portable backupsPortable और easy to use।
Optical DiscCD/DVD based archival या boot mediaOffline physical medium; bootable media के लिए useful।
Magnetic TapeLarge-scale archival/enterprise backupHigh-capacity long-term backup scenarios में उपयोगी।
Network StorageCentralized backupMultiple systems से centralized access।
Cloud StorageOff-site backupRemote access और geographic separation का लाभ।
Important: Critical backup को केवल उसी computer के internal drive पर रखना ideal नहीं है, क्योंकि वही hardware failure disaster में original और backup दोनों को प्रभावित कर सकता है।

5. RAID Systems

RAID (Redundant Array of Independent Disks) multiple physical disks को एक logical storage arrangement में organize करने की technology है। RAID का उद्देश्य configuration के अनुसार performance, redundancy या दोनों को improve करना हो सकता है।

RAID 0 — Striping

Data multiple disks पर stripes में distribute होता है। Performance improve हो सकती है, लेकिन redundancy नहीं होती। एक disk failure से array का data unavailable हो सकता है।

RAID 1 — Mirroring

Data की copy दूसरे disk पर mirror की जाती है। एक disk fail होने पर दूसरे disk से data उपलब्ध रह सकता है।

RAID 5

Striping के साथ distributed parity का उपयोग करता है। Typical implementation में एक disk failure के बाद data recover किया जा सकता है।

RAID 6

Dual distributed parity के कारण RAID 5 की तुलना में अधिक disk-failure tolerance देता है, सामान्यतः दो disk failures तक।

RAID 10

Mirroring और striping का combination है। Performance और redundancy दोनों के लिए उपयोगी, लेकिन अधिक disks की आवश्यकता होती है।

RAIDMain TechniqueRedundancyमुख्य उद्देश्य
0StripingनहींPerformance
1MirroringहाँRedundancy
5Striping + ParityहाँBalance of storage/performance/redundancy
6Striping + Dual ParityहाँHigher fault tolerance
10Mirror + StripeहाँPerformance + redundancy
Exam Point: RAID को complete backup का replacement नहीं माना जाना चाहिए। RAID primarily storage availability/redundancy प्रदान करता है; accidental deletion, malware या logical corruption से अलग backup की आवश्यकता रह सकती है।

6. Preparation of Bootable CD

Bootable CD ऐसी optical disc है जिसमें bootable image/files होते हैं और computer उस disc से operating system installer या recovery environment start कर सकता है। आज USB boot media अधिक common है, लेकिन syllabus में bootable CD एक महत्वपूर्ण concept है।

Bootable CD तैयार करने के Basic Steps

Step 1: Required operating system/recovery ISO image प्राप्त करें।
Step 2: CD/DVD writing software खोलें जो ISO image को bootable disc के रूप में burn कर सके।
Step 3: Burn/Write Image option select करें; ISO को केवल normal data file की तरह copy न करें।
Step 4: Suitable blank CD/DVD insert करें।
Step 5: Write speed और disc settings select करके burning process शुरू करें।
Step 6: Burning complete होने के बाद disc verify करें।
Step 7: Test के लिए system को disc से boot करें और आवश्यकता होने पर boot order में optical drive को enable/select करें।
Note: Modern systems में UEFI और USB boot media के कारण bootable USB आमतौर पर CD की तुलना में अधिक practical है।

7. Linux में crontab द्वारा Automated Backup

cron Linux/Unix-like systems में scheduled jobs automatically execute करने की सुविधा देता है। crontab user की scheduled cron jobs को define करने के लिए उपयोग किया जाता है। इसके माध्यम से backup command को daily, weekly या किसी निर्धारित schedule पर automatically run कराया जा सकता है।

Crontab खोलना

$ crontab -e

Crontab Format

minute hour day-of-month month day-of-week command * * * * * command
FieldRange / Meaning
Minute0–59
Hour0–23
Day of Month1–31
Month1–12
Day of Week0–7, implementation में Sunday के लिए 0 या 7 commonly used

Simple Daily Backup Example

मान लें user के home directory का backup /backup directory में रखना है। एक simple archive command:

tar -czf /backup/home-backup.tar.gz /home/student

इसे रोज रात 11:00 बजे चलाने के लिए crontab entry का example:

0 23 * * * tar -czf /backup/home-backup.tar.gz /home/student

Backup Script के साथ crontab

Real-world setup में backup commands को एक script में रखना अधिक manageable हो सकता है।

#!/bin/bash SOURCE="/home/student" DEST="/backup" DATE=$(date +%Y-%m-%d) tar -czf "$DEST/home-$DATE.tar.gz" "$SOURCE"

मान लें script /home/student/backup.sh पर है। इसे executable बनाने के बाद:

$ chmod +x /home/student/backup.sh $ crontab -e

Daily 11:00 PM:

0 23 * * * /home/student/backup.sh

Crontab Management Commands

$ crontab -e # Edit jobs $ crontab -l # List current jobs $ crontab -r # Remove current user's crontab
Practical Caution: Automated backup में destination path, permissions, available storage, log handling और restore testing carefully configure करें। Important backup को केवल उसी disk/partition पर रखना hardware failure के विरुद्ध पर्याप्त protection नहीं देता।

8. Disaster Prevention & Backup Planning

Disaster Prevention का उद्देश्य data loss और system downtime के impact को पहले से कम करना है। Backup strategy इसका एक महत्वपूर्ण भाग है, लेकिन इसके साथ preventive controls और recovery planning भी आवश्यक हैं।

Basic Disaster Prevention Plan

1. Identify: Critical data और systems identify करें।
2. Schedule: Regular backup schedule तय करें।
3. Separate: Backup की एक copy अलग storage/location पर रखें।
4. Protect: Backup access को unauthorized users से protect करें।
5. Verify: Backup jobs और backup files verify करें।
6. Test Restore: समय-समय पर restore करके recovery process test करें।
7. Document: Backup location, schedule और restore procedure document करें।
