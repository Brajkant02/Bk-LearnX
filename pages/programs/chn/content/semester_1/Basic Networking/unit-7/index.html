7. Presentation and Session Layer

Session Layer Functions • Token Management • Session Layer Protocols • Presentation Layer Functions • Presentation Layer Protocols

1. Introduction

OSI (Open Systems Interconnection) model में Session Layer और Presentation Layer Application Layer के नीचे स्थित होती हैं। Session Layer मुख्य रूप से दो communicating applications के बीच session establish, manage और terminate करने से संबंधित है, जबकि Presentation Layer data के format, translation, encryption और compression जैसी representation-related services पर focus करती है।

OSI MODEL 7 Application 6 Presentation ← Data Representation 5 Session ← Communication Session Management 4 Transport 3 Network 2 Data Link 1 Physical
Exam Definition: Session Layer communication session को establish, manage और terminate करती है तथा dialog control, synchronization और token management जैसी services provide कर सकती है। Presentation Layer sender और receiver के बीच data representation को compatible बनाने के लिए translation, formatting, encryption/decryption और compression/decompression जैसी functions से संबंधित है।

2. Session Layer

Session Layer OSI model की Layer 5 है। इसका primary purpose communicating applications के बीच logical session को establish और manage करना है। यह यह सुनिश्चित करने में सहायता करती है कि communication session properly organized हो और आवश्यकता पड़ने पर synchronized manner में continue या recover किया जा सके।

Session क्या है?

Session दो applications/processes के बीच communication का logical period है। उदाहरण के लिए, जब कोई application दूसरे system की application के साथ communication शुरू करती है, तो उस communication को एक session के रूप में manage किया जा सकता है।

Application A Application B │ │ ▼ ▼ ┌────────────── SESSION LAYER ──────────────┐ │ Establish Session │ │ Manage Dialog │ │ Synchronization │ │ Token Management │ │ Terminate Session │ └───────────────────────────────────────────┘

3. Functions of Session Layer

1. Session Establishment

Communication शुरू होने पर applications के बीच session establish करने में सहायता करती है।

2. Session Maintenance

Communication के दौरान session को manage और maintain करने में सहायता करती है।

3. Session Termination

Communication complete होने पर session को properly terminate करने में सहायता करती है।

4. Dialog Control

Communication में कौन-सा side कब transmit करेगा, इसे organize करने में सहायता करता है।

5. Synchronization

Long communication को synchronization points/checkpoints के माध्यम से organize करने में सहायता करता है।

6. Token Management

कुछ communication situations में critical operations पर control/token किस participant के पास होगा, इसे manage करने की concept provide करता है।

Session Establishment → Data Transfer → Termination

Step 1: Session establish किया जाता है।
Step 2: Applications के बीच data exchange होता है।
Step 3: Dialog और synchronization को manage किया जाता है।
Step 4: Communication complete होने पर session terminate किया जाता है।

4. Dialog Control

Dialog Control Session Layer की important functionality है। इसका उद्देश्य communication के दौरान data exchange का coordination करना है। यह determine करने में सहायता करता है कि communication half-duplex या full-duplex style में किस प्रकार proceed करेगा।

Half-Duplex

Half-duplex communication में दोनों sides communicate कर सकती हैं, लेकिन एक समय पर communication primarily एक direction में होता है। Turn बदलने के बाद दूसरी side transmit करती है।

Device A ─────────────► Device B transmission Device A ◄───────────── Device B next turn

Full-Duplex

Full-duplex communication में दोनों sides simultaneously data transmit और receive कर सकती हैं।

Device A ◄══════════════► Device B simultaneous communication
Exam Point: Dialog control communication session में data exchange के direction/turn को organize करने की concept है।

5. Synchronization

Large data transfer या long communication session में यदि communication बीच में interrupt हो जाए तो पूरे transfer को शुरुआत से दोबारा करना inefficient हो सकता है। Session Layer की synchronization concept communication में checkpoints establish करने में सहायता करती है।

Checkpoint Concept

DATA TRANSFER Start │ ▼ Part 1 ─── Checkpoint 1 │ ▼ Part 2 ─── Checkpoint 2 │ ▼ Part 3 ─── Checkpoint 3 │ ▼ Part 4 │ ▼ Complete

यदि transfer में failure होता है, तो synchronization mechanism के concept के अनुसार communication को last valid checkpoint के आसपास resume करने का advantage मिल सकता है, बजाय पूरे process को unnecessarily repeat करने के।

6. Token Management

Token Management Session Layer से associated एक concept है जिसमें communication के दौरान certain critical activity पर control किस participant के पास होगा, इसे coordinate किया जाता है। Token को एक logical permission की तरह समझ सकते हैं। जिस participant के पास token होता है, उसे specific operation perform करने की अनुमति मिलती है।

Token की आवश्यकता क्यों?

  • Simultaneous access से होने वाले conflicts को reduce करने के लिए।
  • Shared operation को coordinate करने के लिए।
  • Dialog में controlled access maintain करने के लिए।
  • Communication participants के बीच turn/permission manage करने के लिए।
TOKEN │ ▼ ┌─────────┐ │ Device A│ └────┬────┘ │ token transfer ▼ ┌─────────┐ │ Device B│ └────┬────┘ │ token transfer ▼ ┌─────────┐ │ Device C│ └─────────┘
Simple Definition: Token management communication session में permission/control token को manage करके participants के access और dialog को coordinate करने की concept है।

7. Session Layer Protocols

Session Layer के नाम से पढ़ाए जाने वाले protocols/services historical OSI context में session establishment, dialog management और synchronization जैसी functionality से संबंधित रहे हैं। Practical networking में कई session-related functions application और transport protocols द्वारा भी implement हो सकते हैं।

RPC – Remote Procedure Call

RPC एक mechanism है जिसमें application किसी remote system पर available procedure/function को इस तरह invoke कर सकती है जैसे वह local call हो। इसके पीछे communication, request और response का coordination होता है।

NetBIOS

NetBIOS (Network Basic Input/Output System) एक historical networking interface/service है जो network applications के बीच communication और session-oriented services provide करने के लिए उपयोग हुआ है।

ZIP और NCP

OSI/session-layer discussions में ZIP (Zone Information Protocol) और कुछ historical protocol stacks में session-related services के examples मिलते हैं। Protocol mapping हमेशा exact one-to-one नहीं होती; modern TCP/IP architecture में OSI की upper-layer responsibilities कई बार combined application protocols में दिखाई देती हैं।

Protocol / MechanismBasic Purpose
RPCRemote procedure/function invocation
NetBIOSNetwork application/session-oriented communication services
Historical OSI session servicesSession establishment, dialog and synchronization support
Exam Tip: अगर question में “Session Layer Protocols” पूछा जाए, तो protocol का नाम लिखने के साथ उसका basic purpose भी जरूर लिखें।

8. Presentation Layer

Presentation Layer OSI model की Layer 6 है। इसका primary focus data को ऐसे format में represent करना है जिसे communicating systems correctly understand और process कर सकें। इसलिए इसे अक्सर Translation Layer भी कहा जाता है।

Presentation Layer की आवश्यकता

Different computer systems data को internally अलग-अलग formats में represent कर सकते हैं। Presentation Layer का purpose data representation को compatible बनाना है ताकि sender द्वारा भेजा गया information receiver के लिए meaningful form में उपलब्ध हो।

Sender Application │ ▼ Presentation Layer ┌───────────────────────────────┐ │ Translation / Formatting │ │ Encryption / Decryption │ │ Compression / Decompression │ └───────────────────────────────┘ │ ▼ Network │ ▼ Presentation Layer │ ▼ Receiver Application

9. Functions of Presentation Layer

1. Data Translation

Different data representation formats के बीच conversion/translation में सहायता।

2. Data Formatting

Data को agreed representation और syntax के अनुसार organize करना।

3. Encryption

Confidentiality के लिए data को encoded/encrypted representation में transform करने की functionality से संबंधित।

4. Decryption

Receiver side पर encrypted data को readable/original representation में transform करने में सहायता।

5. Compression

Data size reduce करने में सहायता ताकि transmission/storage efficiency improve हो सके।

6. Decompression

Compressed data को receiver side पर usable form में restore करने की प्रक्रिया।

Presentation Layer के तीन सबसे important concepts

FunctionMeaning
TranslationData representation/format conversion
EncryptionData को secure representation में transform करना
CompressionData size reduce करना

10. Data Translation and Representation

Different systems में character encoding, numeric representation और data structures अलग हो सकते हैं। Presentation layer conceptually data को common/compatible representation में translate करने की भूमिका निभाती है।

Example

मान लें sender system किसी text को एक particular character encoding में represent करता है और receiver system दूसरी encoding use करता है। Communication architecture में representation conversion की आवश्यकता हो सकती है ताकि receiver उस text को correctly interpret कर सके।

SENDER FORMAT │ ▼ TRANSLATION / ENCODING │ ▼ COMMON REPRESENTATION │ ▼ TRANSMISSION │ ▼ DECODING / TRANSLATION │ ▼ RECEIVER FORMAT

Common Representation Examples

  • Character encoding जैसे ASCII और Unicode families।
  • Structured data representation जैसे XML/JSON application-level examples।
  • Image/audio/video data के standardized formats।
Important: Modern TCP/IP systems में data representation अक्सर application protocols और libraries के द्वारा handled होती है; OSI Presentation Layer एक conceptual layer है।

11. Encryption, Decryption, Compression और Decompression

Encryption

Encryption में readable/plain information को an encoded form में transform किया जाता है ताकि unauthorized party के लिए information को directly समझना कठिन हो। Receiver appropriate key/mechanism का उपयोग करके उसे decrypt कर सकता है।

Plain Data │ ▼ Encryption + Key │ ▼ Cipher/Encrypted Data │ ▼ Network │ ▼ Decryption + Key │ ▼ Original/Readable Data

Compression

Compression data representation को अधिक compact बनाकर size reduce करने की technique है। इससे storage और transmission efficiency improve हो सकती है।

Compression के Types

TypeMeaningExample Concept
LosslessOriginal data को exactly recover किया जा सकता हैZIP, PNG
Lossyकुछ information discard करके size significantly reduce किया जाता हैJPEG, common multimedia compression
Remember: Encryption का main goal security/confidentiality से related है, जबकि Compression का main goal data size reduce करना है।

12. Presentation Layer Protocols

OSI Presentation Layer के protocols/services data representation, encoding, encryption, compression या structured data interchange से संबंधित हो सकते हैं। Modern networks में ये responsibilities अक्सर application-layer protocols और formats में combined मिलती हैं।

TLS/SSL – Security and Representation Context

TLS secure communication के लिए cryptographic protection provide करता है। इसे strict OSI mapping में pure Presentation Layer protocol कहना उचित नहीं है; practical TCP/IP architecture में TLS application और transport के बीच security layer की तरह काम करता है।

MIME

MIME (Multipurpose Internet Mail Extensions) electronic messages में different content types और media representations identify करने के लिए विकसित हुआ। यह application-level technology है, लेकिन data representation के context में Presentation Layer concepts से commonly associated किया जा सकता है।

ASN.1

ASN.1 (Abstract Syntax Notation One) data structures को machine-independent तरीके से describe करने का standardized notation है। इसके साथ encoding rules data को transmission representation में encode करने में सहायता करते हैं।

XDR

XDR (External Data Representation) एक standard data representation mechanism है जो different systems के बीच structured data को machine-independent representation में encode करने के लिए उपयोग होता है। RPC systems में इसका उपयोग जाना जाता है।

TechnologyRole / Use
ASN.1Abstract data structure representation
XDRMachine-independent external data representation
MIMEContent type/media representation in Internet messaging
TLSCryptographic protection for network communication; not a strict OSI Layer-6-only protocol
Exam Note: OSI layers और real-world TCP/IP protocol mapping exact one-to-one नहीं है। इसलिए “Presentation Layer Protocols” के answer में protocol का practical role और उसका actual architecture context लिखना answer को अधिक accurate बनाता है।

13. Session Layer vs Presentation Layer

BasisSession LayerPresentation Layer

Main FocusCommunication session managementData representation
Major FunctionsSession establishment, dialog control, synchronization, token management, terminationTranslation, formatting, encryption/decryption, compression/decompression
CommunicationSession coordinationData format/representation coordination
Simple Keyword“Session को manage करना”“Data को understandable बनाना”
Easy Trick: Session = बातचीत का management और Presentation = data की presentation/representation.

14. Combined Working of Session & Presentation Layers

SENDER APPLICATION │ ▼ ┌───────────────────────────┐ │ PRESENTATION LAYER │ │ Translation │ │ Encryption │ │ Compression │ └─────────────┬─────────────┘ │ ▼ ┌───────────────────────────┐ │ SESSION LAYER │ │ Establish / Manage │ │ Dialog / Token / Sync │ │ Terminate │ └─────────────┬─────────────┘ │ ▼ TRANSPORT LAYER │ ▼ NETWORK │ ▼ RECEIVER SIDE │ ▼ SESSION MANAGEMENT │ ▼ DATA PRESENTATION │ ▼ RECEIVER APPLICATION

इस flow से याद रखें कि Session Layer communication conversation/session को manage करती है, जबकि Presentation Layer communication में जाने वाले data के representation को manage करने की concept रखती है।
