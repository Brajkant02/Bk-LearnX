Question 21: Explain the accessibility of private, protected and public data members in inheritance.

Access Control in Inheritance

Java access modifiers determine where the variables and methods of a class can be accessed. When one class inherits another class, the accessibility of the superclass members depends on their access modifiers.

1. Private Members

private members are directly accessible only within the class in which they are declared. A subclass cannot access them directly. However, private data can be accessed indirectly through the superclass's public or protected methods.

2. Protected Members

protected members are accessible to classes in the same package. In addition, a subclass in another package can access protected members through inheritance, subject to Java's protected access rules.

3. Public Members

public members can be accessed by classes in any package, provided the declaring class itself is accessible. Therefore, public members remain accessible in subclasses.

4. Default (Package-Private) Members

If no access modifier is specified for a member, it receives default or package-private access. Such members are accessible only to classes in the same package. A subclass in another package cannot access them directly.

Java Program Example

In this example, the superclass contains private, protected, and public variables. The subclass directly accesses the protected and public members, while the private member is accessed through a public method of the superclass.

Java ProgramMember Accessibility
class Parent {
    private int privateData = 10;
    protected int protectedData = 20;
    public int publicData = 30;

    public int getPrivateData() {
        return privateData;
    }
}

class Child extends Parent {
    void display() {
        System.out.println("Private data: " + getPrivateData());
        System.out.println("Protected data: " + protectedData);
        System.out.println("Public data: " + publicData);
    }
}

class AccessDemo {
    public static void main(String[] args) {
        Child obj = new Child();
        obj.display();
    }
}
Output
Private data: 10
Protected data: 20
Public data: 30

Conclusion

In inheritance, public and protected members are accessible to subclasses. Private members cannot be accessed directly in a subclass, but they can be accessed through methods of the superclass. Access modifiers provide data security and controlled access.

Question 22: What is an Interface in Java? Explain how to define and implement an interface with a program.

Interface in Java

An interface in Java is a reference type that defines a contract for methods. It specifies which methods a class must provide when it implements the interface. An interface is declared using the interface keyword, and a class implements it using the implements keyword.

In a basic syllabus-level interface, methods are generally public and abstract. Interface variables are implicitly public static final, which means they are constants. An interface object cannot be created directly.

Defining an Interface

The general syntax for creating an interface is given below:

SyntaxInterface Declaration
interface InterfaceName {
    void methodName();
}

Implementing an Interface

When a class implements an interface, it must provide implementations for all its abstract methods. The implemented methods should be declared public.

The interface declares the method, and the implementing class provides its actual code.

Advantages of Interface

  1. An interface provides abstraction and separates implementation details.
  2. A common contract can be defined for different classes.
  3. Java supports multiple inheritance of type by allowing a class to implement multiple interfaces.
  4. It helps make code flexible and loosely coupled.

Question 23: Differentiate between Class and Interface in Java.

Class

A class is a blueprint or template from which objects are created. It can contain data members, constructors, and methods. An object of a class can be created using the new keyword.

Interface

An interface defines a contract that an implementing class must follow. A basic interface declares abstract methods. An interface object cannot be created directly.

Question 24: What is an Abstract Class in Java? Explain its characteristics with an example.

Abstract Class

An abstract class is a class declared using the abstract keyword. It is used to define common properties and behaviour. An object of an abstract class cannot be created directly. It is used by extending it in another class.

Characteristics of Abstract Class

  1. The abstract keyword is used to declare an abstract class.
  2. An object of an abstract class cannot be created directly.
  3. It can contain both abstract methods and normal (concrete) methods.
  4. It can contain instance variables, static variables, and constructors.
  5. A subclass extends the abstract class and implements its abstract methods; otherwise, the subclass must also be declared abstract.
  6. An abstract class is used to share common code among related classes.

Abstract Method

An abstract method has only a declaration and no body. Its implementation is provided by overriding it in a subclass.

SyntaxAbstract Class and Method
abstract class ClassName {
    abstract void methodName();

    void display() {
        System.out.println("Concrete method");
    }
}

Java Program

Java ProgramAbstract Class Example
abstract class Shape {
    abstract double area();

    void message() {
        System.out.println("Area of shape:");
    }
}

class Circle extends Shape {
    double radius = 5;

    double area() {
        return 3.14 * radius * radius;
    }
}

class AbstractDemo {
    public static void main(String[] args) {
        Circle c = new Circle();
        c.message();
        System.out.println(c.area());
    }
}
Output
Area of shape:
78.5

Explanation

Shape is an abstract class containing the abstract method area() and the concrete method message(). The Circle class extends Shape and provides the body of the area() method. In the main method, a Circle object is created and both methods are called.

Question 26: What is Polymorphism in Java? Explain its types with examples.

Polymorphism

Polymorphism is an important feature of OOP. It means “many forms,” where the same name or reference can show different behaviour in different situations. Polymorphism helps make Java programs flexible and reusable.

Types of Polymorphism

1. Compile-Time Polymorphism (Static Binding)

Compile-time polymorphism is achieved through method overloading. In this technique, multiple methods in the same class have the same name but different parameter lists. The compiler decides which method to call based on the arguments.

2. Run-Time Polymorphism (Dynamic Binding)

Run-time polymorphism is achieved through method overriding. In this technique, a subclass redefines a superclass method with its own implementation. The overridden method that executes is decided at runtime based on the actual object.

Advantages of Polymorphism

  1. Code reusability increases.
  2. The program becomes flexible and extensible.
  3. Different objects can be handled through a common interface/reference.
  4. Method overloading allows different input forms of the same operation to be handled.

Question 27: Differentiate between Method Overloading and Method Overriding with examples.

Method Overloading

When two or more methods with the same name are defined in a class but have different numbers, types, or orders of parameters, it is called method overloading. It is an example of compile-time polymorphism. Changing only the return type does not create method overloading.

Method Overriding

When a subclass redefines a method already present in its superclass using the same signature and its own implementation, it is called method overriding. It is an example of run-time polymorphism. The return type must be compatible, and the access level cannot be made less restrictive.

Question 28: Explain Constructor Overloading in Java. Differentiate between Constructor Overloading and Method Overloading.

Constructor Overloading

When more than one constructor is defined in a class and each constructor has a different parameter list, it is called constructor overloading. It allows an object to be created with different sets of initial values.

A constructor has the same name as its class and does not have a return type. Constructor overloading is an example of compile-time polymorphism.

Java Program

Java ProgramConstructor Overloading
class Student {
    int rollNo;
    String name;

    Student() {
        rollNo = 0;
        name = "Not Assigned";
    }

    Student(int r) {
        rollNo = r;
        name = "Unknown";
    }

    Student(int r, String n) {
        rollNo = r;
        name = n;
    }

    void display() {
        System.out.println(rollNo + " - " + name);
    }
}

class ConstructorDemo {
    public static void main(String[] args) {
        Student s1 = new Student();
        Student s2 = new Student(101);
        Student s3 = new Student(102, "Aman");

        s1.display();
        s2.display();
        s3.display();
    }
}
Output
0 - Not Assigned
101 - Unknown
102 - Aman

Difference Between Constructor Overloading and Method Overloading

BasisConstructor OverloadingMethod Overloading
PurposeInitialises an object in different ways.Performs the same operation with different parameters.
NameAll constructors have the same name as the class.Overloaded methods have the same name.
Return TypeA constructor has no return type.A method can have a return type; changing only the return type does not constitute overloading.
InvocationCalled when an object is created.Invoked through a method call statement.
InheritanceConstructors are not inherited.Methods can be inherited and overloaded.

Advantages

  1. Objects can be created with different initial values.
  2. Multiple initialization options are available within the same class.
  3. Program readability and flexibility improve.

Question 29: Explain Upcasting and Downcasting in Java with examples. Differentiate between them.

Type Casting in Inheritance

In inheritance, conversion between superclass and subclass references is called casting. Java mainly uses Upcasting and Downcasting.

1. Upcasting

Converting a reference of subclass type into a reference of superclass type is called upcasting. It can happen automatically because every subclass object is also an object of its superclass. Through a superclass reference, only members declared in the superclass can be accessed, but an overridden instance method executes according to the actual object.

2. Downcasting

Converting a reference of superclass type into a reference of subclass type is called downcasting. It requires an explicit cast. Downcasting is valid only when the reference actually refers to a compatible subclass object. An invalid cast can cause a ClassCastException.

Java Program

Java ProgramUpcasting and Downcasting
class Animal {
    void eat() {
        System.out.println("Animal eats food");
    }
}

class Dog extends Animal {
    void bark() {
        System.out.println("Dog barks");
    }
}

class CastingDemo {
    public static void main(String[] args) {
        Dog d = new Dog();

        // Upcasting
        Animal a = d;
        a.eat();

        // Safe downcasting
        if (a instanceof Dog) {
            Dog d2 = (Dog) a;
            d2.bark();
        }
    }
}
Output
Animal eats food
Dog barks

AccessAccess is limited to members declared in the superclass.Additional subclass members can also be accessed.
UseUsed to handle subclass objects through a common superclass reference.Used to access subclass-specific behaviour/members.
Exam Tip: Before downcasting, using the instanceof operator to check the object type is a safer approach.

Question 30: What is Exception Handling in Java? Explain its importance, advantages and working.

Exception

An exception is an unwanted event or error condition that occurs during program execution and may disturb the normal flow. Examples include dividing by zero, accessing an invalid array index, or opening a file that is not available.

Exception Handling

Exception handling in Java is a mechanism for handling runtime errors so that the normal flow of a program can continue whenever possible. Java uses the try, catch, finally, throw, and throws keywords for exception handling. Their detailed use is explained in the following questions.

Why Exception Handling is Important?

  1. Prevents Abnormal Termination: Handling an exception can prevent a program from terminating unexpectedly.
  2. Maintains Normal Flow: Alternate handling code can be provided for an error situation.
  3. Error Separation: The main program logic can be kept separate from error-handling code.
  4. Meaningful Messages: Understandable error messages can be displayed to the user.
  5. Easy Debugging: Exception information helps identify the cause of an error.

Advantages of Exception Handling

  • The program becomes more reliable and robust.
  • Runtime errors can be handled in an organized way.
  • Separate catch blocks can be written to handle different exceptions raised in the same try block.
  • Cleanup tasks, such as closing resources, can be performed in a finally block.
  • An exception can also be propagated further through the call stack.

Working of Exception Handling

When a statement generates an exception, the Java runtime stops normal execution at that point and searches for a matching exception handler. If a matching catch block is found, its code is executed. The applicable finally block then executes, and the program may continue. If no handler is found, the exception is propagated through the call stack; if it remains uncaught, the program may terminate.

Simple Java Program

In this program, if the denominator is zero during division, an ArithmeticException is generated. The catch block handles that exception.

Java ProgramException Handling Overview
class ExceptionDemo {
    public static void main(String[] args) {
        int a = 10;
        int b = 0;

        try {
            int result = a / b;
            System.out.println(result);
        } catch (ArithmeticException e) {
            System.out.println("Cannot divide by zero");
        }

        System.out.println("Program continues...");
    }
}
Output
Cannot divide by zero
Program continues...

Types of Exceptions (Overview)

  1. Checked Exceptions: These are checked by the compiler at compile time. Examples: IOException, SQLException.
  2. Unchecked Exceptions: These occur at runtime and are generally subclasses of RuntimeException. Examples: ArithmeticException, NullPointerException, and ArrayIndexOutOfBoundsException.

Thus, exception handling makes a Java program safer and more organized when dealing with unexpected runtime conditions.
