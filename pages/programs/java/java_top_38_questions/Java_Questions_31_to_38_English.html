Question 31: Explain try, catch and finally blocks in Java with an example.

Exception Handling Blocks

Java uses the try, catch, and finally blocks for exception handling. These blocks help handle runtime exceptions and maintain the normal execution of a program whenever possible.

1. try Block

The try block contains statements that may generate an exception. If an exception occurs in the try block, Java attempts to execute a matching catch block.

2. catch Block

The catch block handles an exception. It specifies the exception type and a reference variable. Multiple catch blocks can be used with one try block to handle different types of exceptions. A catch block for a specific exception must be placed before a catch block for a general exception.

3. finally Block

The finally block contains code that should generally execute after try/catch processing, such as closing a file or another resource. Under normal execution, the finally block executes whether or not an exception occurs. Its execution is not guaranteed in situations such as an abrupt JVM termination.

Syntax

Syntaxtry-catch-finally 
try {
    // Statements that may cause an exception
} catch (ExceptionType e) {
    // Exception handling code
} finally {
    // Cleanup code
}

Java Program

Java Programtry, catch and finally 
class TryCatchFinallyDemo {
    public static void main(String[] args) {
        int a = 20;
        int b = 0;

        try {
            int result = a / b;
            System.out.println("Result: " + result);
        } catch (ArithmeticException e) {
            System.out.println("Cannot divide by zero");
        } finally {
            System.out.println("Finally block executed");
        }

        System.out.println("Program ended");
    }
}
Output 
Cannot divide by zero
Finally block executed
Program ended

Multiple catch Blocks

Multiple catch blocks can be written for different exceptions in one try block. For example, ArithmeticException and ArrayIndexOutOfBoundsException can be handled separately.

Java ProgramMultiple catch Blocks 
class MultipleCatchDemo {
    public static void main(String[] args) {
        try {
            int[] numbers = {10, 20};
            System.out.println(numbers[5]);
        } catch (ArithmeticException e) {
            System.out.println("Arithmetic error");
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("Invalid array index");
        } catch (Exception e) {
            System.out.println("Some other exception");
        }
    }
}
Output 
Invalid array index

Advantages

  • Runtime exceptions can be handled.
  • It helps prevent a program from terminating unexpectedly.
  • Multiple catch blocks allow different errors to be handled in different ways.
  • Cleanup operations can be performed in the finally block.

Question 32: Differentiate between throw and throws keywords in Java with examples.

throw Keyword

The throw keyword is used inside a method or block to explicitly throw an exception object. The normal flow of the program stops at that point, and Java searches for a matching exception handler.

throws Keyword

The throws keyword is used in a method declaration. It specifies which checked exceptions may be propagated out of the method. The code that calls the method can handle the exception or declare it further.

Difference Between throw and throws

Basis throw throws
Purpose Explicitly throws an exception. Declares an exception that may be propagated by a method.
Position Used inside a method or block as a statement. Used in a method declaration.
Followed By An exception object, such as new ArithmeticException(). Exception class names, such as IOException.
Number One exception object is thrown in a single throw statement. Can declare one or more exception types.
Responsibility Actually throws an exception. Declares/propagates exception-handling responsibility to the caller.

Example of throw

Java Programthrow Keyword 
class ThrowDemo {
    public static void main(String[] args) {
        int age = 15;

        try {
            if (age < 18) {
                throw new IllegalArgumentException(
                    "Age must be 18 or above");
            }
            System.out.println("Eligible");
        } catch (IllegalArgumentException e) {
            System.out.println(e.getMessage());
        }
    }
}
Output 
Age must be 18 or above

Example of throws

Java Programthrows Keyword 
import java.io.IOException;

class ThrowsDemo {
    static void checkFile() throws IOException {
        throw new IOException("File not found");
    }

    public static void main(String[] args) {
        try {
            checkFile();
        } catch (IOException e) {
            System.out.println(e.getMessage());
        }
    }
}
Output 
File not found
Remember: throw throws an exception, whereas throws declares possible exceptions in a method declaration.

Question 33: Explain built-in and user-defined exceptions in Java. How can we create our own exception class?

Built-in Exceptions

Java provides many exception classes in advance. These are called built-in exceptions. They represent common programming errors and exceptional conditions.

Common Built-in Exceptions

Exception Description
ArithmeticException An arithmetic error, such as dividing an integer by zero.
NullPointerException Occurs when an instance member is accessed through a null reference.
ArrayIndexOutOfBoundsException Occurs when an array is accessed outside its valid index range.
NumberFormatException Occurs when an invalid string is converted into a numeric value.
IOException Occurs when an error happens during an input/output operation.
ClassNotFoundException Occurs when a requested class cannot be found, for example, during certain class-loading operations.

User-Defined Exceptions

When a programmer creates a new exception class according to an application's requirements, it is called a user-defined or custom exception. To create a custom checked exception, the class can extend Exception. To create an unchecked custom exception, it can extend RuntimeException.

Steps to Create User-Defined Exception

  1. Declare a new class.
  2. Make it inherit from the Exception class.
  3. Pass the message to the superclass constructor from the constructor.
  4. Check the condition and throw the custom exception using the throw keyword.
  5. Handle it in a try-catch block.

Java Program

Java ProgramCustom Exception 
class InvalidAgeException extends Exception {
    InvalidAgeException(String message) {
        super(message);
    }
}

class CustomExceptionDemo {
    static void checkAge(int age)
            throws InvalidAgeException {
        if (age < 18) {
            throw new InvalidAgeException(
                "Age is below 18");
        }
        System.out.println("You are eligible");
    }

    public static void main(String[] args) {
        try {
            checkAge(16);
        } catch (InvalidAgeException e) {
            System.out.println(e.getMessage());
        }
    }
}
Output 
Age is below 18

Difference Between Built-in and User-Defined Exceptions

Basis Built-in Exception User-Defined Exception
Meaning Already defined in the Java API. Created by the programmer.
Creation There is no need to create it manually. A custom exception class must be defined.
Purpose Represents common runtime or application errors. Represents application-specific error conditions.
Example ArithmeticException, IOException InvalidAgeException, InsufficientBalanceException

Question 34: What is Multithreading? Explain its advantages and differentiate between Multitasking and Multithreading.

Thread

A thread is the smallest unit of execution within a program, also known as a lightweight subprocess. Multiple threads within a Java program can execute independently and concurrently.

Multithreading

Multithreading is the technique of executing multiple threads concurrently within the same program or process. Each thread has its own execution path, while threads in the same process can share memory and resources.

Advantages of Multithreading

  1. Even when one thread is busy with a task, another thread can perform a different task.
  2. Threads within the same process can share common memory and resources.
  3. Keeping multiple tasks in concurrent execution can help make better use of the CPU.
  4. Threads are generally lightweight compared with creating separate processes.
  5. Background and foreground tasks can run concurrently within an application.

Multitasking

Multitasking is the ability of a system to manage and execute multiple tasks or programs during the same period. Different processes or programs may run at the same time.

Difference Between Multitasking and Multithreading

Basis Multitasking Multithreading
Meaning Execution or management of multiple tasks/processes. Execution of multiple threads within one process.
Unit A process or task. A thread.
Memory Processes generally have separate memory spaces. Threads within one process share memory.
Communication Communication between processes may require IPC mechanisms. Shared memory can make communication between threads easier.
Overhead Process management generally has higher overhead. Threads are lightweight, so their overhead is generally lower.
Example Running a browser and a music player at the same time. Managing different browser tabs or background tasks using threads (depending on the implementation).

Question 35: Explain the life cycle of a thread in Java with a diagram.

Thread Life Cycle

A thread passes through different states from its creation until its completion. The official Java thread states are NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, and TERMINATED. In the RUNNABLE state, a thread may be ready to run or may be executing on the CPU.

Different States of Thread

  1. A Thread object has been created, but its start() method has not yet been called.
  2. After start() is called, the thread enters the runnable state. The scheduler may select it for CPU execution.
  3. The thread is waiting to acquire a synchronized lock.
  4. The thread is waiting for another thread to perform an action, such as with wait() or join() without a timeout.
  5. The thread waits for a specified period, such as when using sleep() or a timed join().
  6. The thread's run method has completed, or the thread has ended because of an uncaught exception.

Question 36: Explain how to create a thread in Java by extending Thread class and implementing Runnable interface.

Creating Threads in Java

There are two commonly taught ways to create a thread in Java:

  1. By extending the Thread class.
  2. By implementing the Runnable interface.

1. By Extending Thread Class

In this method, a new class extends the Thread class. The class then overrides the run() method and writes the code that should execute in a separate thread. The object's start() method is called to start the thread. The start() method begins a new execution thread, and the JVM executes the run() method in that thread.

Java ProgramExtending Thread Class 
class MyThread extends Thread {
    public void run() {
        System.out.println("Thread is running");
    }
}

class ThreadClassDemo {
    public static void main(String[] args) {
        MyThread t = new MyThread();
        t.start();
    }
}
Output 
Thread is running

2. By Implementing Runnable Interface

In this method, a class implements the Runnable interface and defines the run() method. A Thread object is then created by passing the Runnable object to the Thread constructor. Finally, start() is called.

Java ProgramImplementing Runnable 
class MyTask implements Runnable {
    public void run() {
        System.out.println("Runnable thread is running");
    }
}

class RunnableDemo {
    public static void main(String[] args) {
        MyTask task = new MyTask();
        Thread t = new Thread(task);
        t.start();
    }
}
Output 
Runnable thread is running

Difference Between Thread Class and Runnable Interface

Basis Extending Thread Implementing Runnable
Method The Thread class must be extended. The Runnable interface must be implemented.
Inheritance The class cannot extend another class because Java supports single class inheritance. The class can also extend another class.
Object The subclass object itself is a Thread. The Runnable task is passed to a Thread object.
Reusability Combines the task and the thread in one class. Keeps the task separate from the Thread and is more flexible.
Preferred Use Useful when the behaviour of the Thread class needs to be customised. Generally preferred for keeping the task separate from the thread.
Important: Call start() to start a thread. Calling run() directly executes it like a normal method in the current thread; it does not start a new thread.

Question 37: Explain thread priorities in Java. How can we set and get the priority of a thread?

Thread Priority

Every Java thread has a priority that gives the thread scheduler a hint about which thread may receive greater preference for execution. Priority is only a scheduling hint; it does not guarantee that a high-priority thread will always execute first.

Priority Range

Java thread priorities range from 1 to 10. The Thread class provides three predefined constants for this purpose:

Constant Value Meaning
MIN_PRIORITY 1 Minimum priority
NORM_PRIORITY 5 Normal/default priority
MAX_PRIORITY 10 Maximum priority

Methods to Set and Get Priority

  • setPriority(int priority): Sets the priority of a thread.
  • getPriority(): Returns the current priority of a thread.

Java Program

Java ProgramSet and Get Thread Priority 
class PriorityDemo {
    public static void main(String[] args) {
        Thread t1 = new Thread(() ->
            System.out.println("Thread 1 running"));

        Thread t2 = new Thread(() ->
            System.out.println("Thread 2 running"));

        t1.setPriority(Thread.MIN_PRIORITY);
        t2.setPriority(Thread.MAX_PRIORITY);

        System.out.println("Priority of t1: "
                           + t1.getPriority());
        System.out.println("Priority of t2: "
                           + t2.getPriority());

        t1.start();
        t2.start();
    }
}
Output (Thread execution order may vary) 
Priority of t1: 1
Priority of t2: 10
Thread 1 running
Thread 2 running

Important Points

  1. The default thread priority is generally 5, which is NORM_PRIORITY.
  2. A new thread generally inherits the priority of its parent thread.
  3. Setting a priority below 1 or above 10 causes an IllegalArgumentException.
  4. A high priority does not guarantee first execution; scheduling depends on the JVM and operating system.

Question 38: What is Thread Synchronization in Java? Explain its need and working with an example.

Thread Synchronization

When multiple threads access and modify the same shared resource or data, data inconsistency or a race condition may occur. Synchronization is used to avoid such situations. In Java, synchronization ensures that only one thread at a time can hold the lock for a particular synchronized section or method.

Need of Synchronization

  1. Prevents Race Conditions: Helps prevent simultaneous conflicting updates to shared data.
  2. Data Consistency: Helps keep the value of a shared resource consistent.
  3. Thread Safety: Controls access to a shared object by multiple threads.
  4. Controlled Access: Allows one thread at a time to enter a critical section protected by the same lock.

synchronized Keyword

The synchronized keyword is used to synchronize a method or block in Java. A synchronized instance method acquires the monitor lock of the current object. A synchronized static method acquires the lock of the associated Class object. A synchronized block acquires the lock of the specified object.

Java Program

In the following program, two threads call the synchronized method of the same object. While one thread holds the lock during method execution, the other thread waits until it can acquire the same lock.

Java ProgramThread Synchronization 
class Table {
    synchronized void printTable(int n) {
        for (int i = 1; i <= 5; i++) {
            System.out.println(n + " x " + i
                               + " = " + (n * i));
        }
    }
}

class ThreadOne extends Thread {
    Table t;

    ThreadOne(Table t) {
        this.t = t;
    }

    public void run() {
        t.printTable(5);
    }
}

class ThreadTwo extends Thread {
    Table t;

    ThreadTwo(Table t) {
        this.t = t;
    }

    public void run() {
        t.printTable(10);
    }
}

class SyncDemo {
    public static void main(String[] args) {
        Table obj = new Table();

        ThreadOne t1 = new ThreadOne(obj);
        ThreadTwo t2 = new ThreadTwo(obj);

        t1.start();
        t2.start();
    }
}
Possible Output 
5 x 1 = 5
5 x 2 = 10
5 x 3 = 15
5 x 4 = 20
5 x 5 = 25
10 x 1 = 10
10 x 2 = 20
10 x 3 = 30
10 x 4 = 40
10 x 5 = 50

It is also possible for the complete table of 10 to be printed first, followed by the table of 5. However, the output from the two threads will not be interleaved while they are executing the synchronized method on the same object.

Advantages of Synchronization

  • Protects shared data.
  • Reduces the possibility of race conditions.
  • Provides controlled access to a critical section.
  • Helps in writing thread-safe code.

Disadvantages

  • Unnecessary synchronization can reduce performance.
  • Incorrect lock ordering can lead to a deadlock.
  • Excessive synchronization can force threads to wait.
Conclusion: Synchronization provides safe and controlled access to shared resources. It should be applied only to necessary critical sections to avoid an unnecessary impact on performance.
