Question 31: Explain try, catch and finally blocks in Java with an example.

Exception Handling Blocks

Java में exception handling के लिए try, catch और finally blocks का उपयोग किया जाता है। इनकी मदद से runtime exception को handle करके program के normal execution को बनाए रखने का प्रयास किया जाता है।

1. try Block

try block के अंदर वह statements लिखे जाते हैं जिनसे exception generate होने की संभावना होती है। यदि try block में exception आती है, तो Java matching catch block को execute करने का प्रयास करता है।

2. catch Block

catch block exception को handle करता है। इसमें exception का type और reference variable दिया जाता है। एक try block के साथ multiple catch blocks भी लिखे जा सकते हैं, ताकि अलग-अलग प्रकार की exceptions को handle किया जा सके। Specific exception का catch block general exception वाले catch block से पहले लिखना चाहिए।

3. finally Block

finally block में वह code लिखा जाता है जिसे सामान्यतः try/catch processing के बाद execute करना होता है, जैसे file या अन्य resource को close करना। Exception आए या न आए, finally block सामान्य execution में execute होता है। JVM के अचानक terminate होने जैसी परिस्थितियों में इसकी execution की guarantee नहीं होती।

Syntax

Syntaxtry-catch-finally
try {
    // Statements that may cause an exception
} catch (ExceptionType e) {
    // Exception handling code
} finally {
    // Cleanup code
}

Java Program

Java Programtry, catch and finally
class TryCatchFinallyDemo {
    public static void main(String[] args) {
        int a = 20;
        int b = 0;

        try {
            int result = a / b;
            System.out.println("Result: " + result);
        } catch (ArithmeticException e) {
            System.out.println("Cannot divide by zero");
        } finally {
            System.out.println("Finally block executed");
        }

        System.out.println("Program ended");
    }
}
Output 
Cannot divide by zero
Finally block executed
Program ended

Multiple catch Blocks

एक try block में अलग-अलग exceptions के लिए multiple catch blocks लिखे जा सकते हैं। उदाहरण के लिए ArithmeticException और ArrayIndexOutOfBoundsException को अलग-अलग handle किया जा सकता है।

Java ProgramMultiple catch Blocks
class MultipleCatchDemo {
    public static void main(String[] args) {
        try {
            int[] numbers = {10, 20};
            System.out.println(numbers[5]);
        } catch (ArithmeticException e) {
            System.out.println("Arithmetic error");
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("Invalid array index");
        } catch (Exception e) {
            System.out.println("Some other exception");
        }
    }
}
Output 
Invalid array index

Advantages

  • Runtime exceptions को handle किया जा सकता है।
  • Program को अचानक terminate होने से बचाने में मदद मिलती है।
  • Multiple catch blocks से अलग-अलग errors को अलग तरीके से handle कर सकते हैं।
  • Finally block में cleanup operations किए जा सकते हैं।

Question 32: Differentiate between throw and throws keywords in Java with examples.

throw Keyword

throw keyword का उपयोग किसी method या block के अंदर explicitly exception object throw करने के लिए किया जाता है। इसके बाद program का normal flow उस point से रुकता है और matching exception handler खोजा जाता है।

throws Keyword

throws keyword method declaration में उपयोग होता है। यह बताता है कि method से कौन-सी checked exception बाहर propagate हो सकती है। Method को call करने वाला code उस exception को handle कर सकता है या आगे declare कर सकता है।

Difference Between throw and throws

Basis throw throws
Purpose Explicitly exception throw करता है। Method द्वारा propagate हो सकने वाली exception declare करता है।
Position Method या block के अंदर statement के रूप में। Method declaration के साथ।
Followed By Exception object, जैसे new ArithmeticException()। Exception class names, जैसे IOException।
Number एक statement में एक exception object throw किया जाता है। एक या अधिक exception types declare कर सकता है।
Responsibility Exception को वास्तव में throw करता है। Exception handling की responsibility caller तक बताता/propagate करता है।

Example of throw

Question 33: Explain built-in and user-defined exceptions in Java. How can we create our own exception class?

Built-in Exceptions

Java में पहले से कई exception classes उपलब्ध हैं। इन्हें built-in exceptions कहते हैं। ये सामान्य programming errors और exceptional conditions को represent करती हैं।

Common Built-in Exceptions

Exception Description
ArithmeticException Arithmetic error, जैसे integer को zero से divide करना।
NullPointerException Null reference के माध्यम से instance member access करने पर।
ArrayIndexOutOfBoundsException Array की valid index range से बाहर access करने पर।
NumberFormatException Invalid string को numeric value में convert करने पर।
IOException Input/output operation के दौरान error होने पर।
ClassNotFoundException Requested class न मिलने पर, जैसे कुछ class-loading operations में।

User-Defined Exceptions

जब programmer अपनी application की requirement के अनुसार नई exception class बनाता है, तो उसे user-defined या custom exception कहते हैं। Custom checked exception बनाने के लिए अपनी class को Exception class से extend किया जा सकता है। Unchecked custom exception के लिए RuntimeException extend किया जा सकता है।

Steps to Create User-Defined Exception

  1. एक नई class declare करें।
  2. उसे Exception class से inherit करें।
  3. Constructor में message को superclass के constructor तक pass करें।
  4. Condition check करके throw keyword से custom exception throw करें।
  5. उसे try-catch block में handle करें।

Java Program

Java ProgramCustom Exception
class InvalidAgeException extends Exception {
    InvalidAgeException(String message) {
        super(message);
    }
}

class CustomExceptionDemo {
    static void checkAge(int age)
            throws InvalidAgeException {
        if (age < 18) {
            throw new InvalidAgeException(
                "Age is below 18");
        }
        System.out.println("You are eligible");
    }

    public static void main(String[] args) {
        try {
            checkAge(16);
        } catch (InvalidAgeException e) {
            System.out.println(e.getMessage());
        }
    }
}
Output 
Age is below 18

Question 34: What is Multithreading? Explain its advantages and differentiate between Multitasking and Multithreading.

Thread

Thread एक program के execution की smallest unit या lightweight sub-process कहलाता है। Java में एक program के अंदर multiple threads independently और concurrently execute हो सकते हैं।

Multithreading

एक ही program या process के अंदर multiple threads को concurrent तरीके से execute करने की technique को multithreading कहते हैं। प्रत्येक thread अपना अलग execution path रखता है, जबकि same process के threads memory और resources share कर सकते हैं।

Advantages of Multithreading

  1. Better Responsiveness: एक thread किसी task में busy हो, तब भी दूसरा thread अन्य task कर सकता है।
  2. Resource Sharing: एक ही process के threads common memory और resources share कर सकते हैं।
  3. Improved CPU Utilization: Multiple tasks को concurrent execution में रखकर CPU का बेहतर उपयोग किया जा सकता है।
  4. Economical: अलग-अलग processes create करने की तुलना में threads सामान्यतः lightweight होते हैं।
  5. Concurrent Operations: एक application में background और foreground tasks साथ चल सकते हैं।

Multitasking

एक system द्वारा एक ही समयावधि में multiple tasks या programs को manage और execute करने की capability को multitasking कहते हैं। इसमें अलग-अलग processes या programs चल सकते हैं।

Difference Between Multitasking and Multithreading

Communication Processes के बीच communication के लिए IPC mechanisms की जरूरत हो सकती है। Shared memory के कारण threads के बीच communication आसान हो सकता है।
Overhead Process management का overhead सामान्यतः अधिक होता है। Threads lightweight होते हैं, इसलिए overhead सामान्यतः कम होता है।
Example Browser और music player साथ चलाना। Browser में अलग-अलग tabs या background tasks को threads से manage करना (implementation पर निर्भर)।

Question 35: Explain the life cycle of a thread in Java with a diagram.

Thread Life Cycle

Java में thread अपने creation से लेकर completion तक अलग-अलग states से गुजरता है। Java के official thread states में NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING और TERMINATED शामिल हैं। RUNNABLE state में thread ready भी हो सकता है या CPU पर execute भी हो सकता है।

Different States of Thread

  1. NEW: Thread object create किया गया है, लेकिन अभी start() method call नहीं हुआ है।
  2. RUNNABLE: start() call होने के बाद thread runnable state में जाता है। Scheduler इसे CPU execution के लिए चुन सकता है।
  3. BLOCKED: Thread किसी synchronized lock को प्राप्त करने के लिए wait कर रहा होता है।
  4. WAITING: Thread किसी दूसरे thread की action का इंतजार कर रहा होता है, जैसे बिना timeout वाला wait() या join()।
  5. TIMED_WAITING: Thread एक specified time तक wait करता है, जैसे sleep() या timed join()।
  6. TERMINATED: Thread का run method complete हो गया है या uncaught exception के कारण thread समाप्त हो गया है।

Question 36: Explain how to create a thread in Java by extending Thread class and implementing Runnable interface.

Creating Threads in Java

Java में thread create करने के दो commonly taught तरीके हैं:

  1. Thread class को extend करके।
  2. Runnable interface को implement करके।

1. By Extending Thread Class

इस method में एक नई class, Thread class को extend करती है। फिर run() method को override करके उस code को लिखा जाता है जिसे अलग thread में execute करना है। Thread start करने के लिए object पर start() call किया जाता है। start() नया execution thread शुरू करता है और JVM उस thread में run() method execute करती है।

Java ProgramExtending Thread Class
class MyThread extends Thread {
    public void run() {
        System.out.println("Thread is running");
    }
}

class ThreadClassDemo {
    public static void main(String[] args) {
        MyThread t = new MyThread();
        t.start();
    }
}
Output 
Thread is running

2. By Implementing Runnable Interface

इस method में एक class Runnable interface implement करती है और run() method define करती है। इसके बाद Runnable object को Thread constructor में pass करके Thread object create किया जाता है। अंत में start() call किया जाता है।

Java ProgramImplementing Runnable
class MyTask implements Runnable {
    public void run() {
        System.out.println("Runnable thread is running");
    }
}

class RunnableDemo {
    public static void main(String[] args) {
        MyTask task = new MyTask();
        Thread t = new Thread(task);
        t.start();
    }
}
Output 
Runnable thread is running

Difference Between Thread Class and Runnable Interface

Basis Extending Thread Implementing Runnable
Method Thread class को extend करना पड़ता है। Runnable interface implement करना पड़ता है।
Inheritance Class किसी दूसरी class को extend नहीं कर सकती क्योंकि Java में single class inheritance है। Class किसी दूसरी class को extend भी कर सकती है।
Object Subclass का object ही Thread होता है। Runnable task को Thread object में pass किया जाता है।
Reusability Task और thread को एक class में combine करता है। Task को Thread से अलग रखता है और अधिक flexible है।
Preferred Use जब Thread class के behaviour को customize करना हो। सामान्यतः task को thread से अलग रखने के लिए preferred approach।
Important: Thread start करने के लिए start() call करें। सीधे run() call करने पर वह सामान्य method की तरह current thread में execute होता है, नया thread start नहीं होता।

Question 37: Explain thread priorities in Java. How can we set and get the priority of a thread?

Thread Priority

Java में प्रत्येक thread की एक priority होती है जो thread scheduler को यह संकेत देती है कि किस thread को execution के लिए अधिक preference दी जा सकती है। Priority एक scheduling hint है; यह guarantee नहीं करती कि high-priority thread हमेशा पहले execute होगा।

Priority Range

Java में thread priority की range 1 से 10 तक होती है। Thread class में इसके लिए तीन predefined constants दिए गए हैं:

Constant Value Meaning
MIN_PRIORITY 1 Minimum priority
NORM_PRIORITY 5 Normal/default priority
MAX_PRIORITY 10 Maximum priority

Methods to Set and Get Priority

  • setPriority(int priority): Thread की priority set करता है।
  • getPriority(): Thread की current priority return करता है।

Java Program

Java ProgramSet and Get Thread Priority
class PriorityDemo {
    public static void main(String[] args) {
        Thread t1 = new Thread(() ->
            System.out.println("Thread 1 running"));

        Thread t2 = new Thread(() ->
            System.out.println("Thread 2 running"));

        t1.setPriority(Thread.MIN_PRIORITY);
        t2.setPriority(Thread.MAX_PRIORITY);

        System.out.println("Priority of t1: "
                           + t1.getPriority());
        System.out.println("Priority of t2: "
                           + t2.getPriority());

        t1.start();
        t2.start();
    }
}
Output (Thread execution order may vary) 
Priority of t1: 1
Priority of t2: 10
Thread 1 running
Thread 2 running

Important Points

  1. Default thread priority सामान्यतः 5 होती है, जो NORM_PRIORITY है।
  2. New thread सामान्यतः अपने parent thread की priority inherit करता है।
  3. Priority 1 से कम या 10 से अधिक set करने पर IllegalArgumentException आती है।
  4. High priority का अर्थ guaranteed first execution नहीं है; scheduling JVM और operating system पर depend करती है।

Question 38: What is Thread Synchronization in Java? Explain its need and working with an example.

Thread Synchronization

जब multiple threads एक ही shared resource या data को access और modify करते हैं, तो data inconsistency या race condition हो सकती है। ऐसी situation से बचने के लिए synchronization का उपयोग किया जाता है। Java में synchronization यह सुनिश्चित करता है कि एक समय में केवल एक thread किसी particular synchronized section या method के lock को hold करे।

Need of Synchronization

  1. Prevents Race Condition: Shared data पर simultaneous conflicting updates को रोकने में मदद करता है।
  2. Data Consistency: Shared resource की value को consistent रखने में मदद मिलती है।
  3. Thread Safety: Multiple threads द्वारा shared object access को नियंत्रित करता है।
  4. Controlled Access: Critical section में एक समय में एक thread को प्रवेश देता है, उसी lock के संदर्भ में।

synchronized Keyword

Java में synchronized keyword का उपयोग method या block को synchronize करने के लिए किया जाता है। Synchronized instance method में current object का monitor lock लिया जाता है। Synchronized static method में संबंधित Class object का lock लिया जाता है। Synchronized block में specified object का lock लिया जाता है।

Java Program

नीचे दिए गए program में दो threads एक ही object के synchronized method को call करते हैं। Method के execution के दौरान एक thread lock hold करता है, इसलिए दूसरा thread उसी lock को प्राप्त करने तक wait करता है।

Java ProgramThread Synchronization
class Table {
    synchronized void printTable(int n) {
        for (int i = 1; i <= 5; i++) {
            System.out.println(n + " x " + i
                               + " = " + (n * i));
        }
    }
}

class ThreadOne extends Thread {
    Table t;

    ThreadOne(Table t) {
        this.t = t;
    }

    public void run() {
        t.printTable(5);
    }
}

class ThreadTwo extends Thread {
    Table t;

    ThreadTwo(Table t) {
        this.t = t;
    }

    public void run() {
        t.printTable(10);
    }
}

class SyncDemo {
    public static void main(String[] args) {
        Table obj = new Table();

        ThreadOne t1 = new ThreadOne(obj);
        ThreadTwo t2 = new ThreadTwo(obj);

        t1.start();
        t2.start();
    }
}
Possible Output 
5 x 1 = 5
5 x 2 = 10
5 x 3 = 15
5 x 4 = 20
5 x 5 = 25
10 x 1 = 10
10 x 2 = 20
10 x 3 = 30
10 x 4 = 40
10 x 5 = 50

यह भी possible है कि पहले 10 की पूरी table print हो और उसके बाद 5 की table। लेकिन एक ही object के synchronized method पर दोनों threads का output interleave नहीं होगा।

Advantages of Synchronization

  • Shared data को protect करता है।
  • Race condition की संभावना कम करता है।
  • Critical section पर controlled access देता है।
  • Thread-safe code लिखने में मदद करता है।

Disadvantages

  • Unnecessary synchronization से performance कम हो सकती है।
  • गलत lock ordering से deadlock की स्थिति बन सकती है।
  • बहुत अधिक synchronization से threads को wait करना पड़ सकता है।
Conclusion: Synchronization shared resources पर safe और controlled access प्रदान करता है। इसे केवल आवश्यक critical sections पर लागू करना चाहिए, ताकि performance पर अनावश्यक असर न पड़े।
