1. Introduction to Version Control

Definition

Version Control एक system है जो files या source code में समय के साथ होने वाले changes को record और manage करता है। इसका उपयोग developers को पुराने versions देखने, changes compare करने और जरूरत पड़ने पर previous version पर वापस जाने में मदद करने के लिए किया जाता है।

Software development में कई developers एक ही project पर काम कर सकते हैं। ऐसी स्थिति में version control changes को व्यवस्थित रखने और collaboration को आसान बनाने में महत्वपूर्ण भूमिका निभाता है।

Exam Point:
Version Control का मुख्य उद्देश्य source code के different versions को track, manage और recover करना है।

2. Version Control

Definition

Version Control system files के changes का history maintain करता है। प्रत्येक important change को एक identifiable version या commit के रूप में record किया जा सकता है।

Importance

  • Changes का history maintain करना।
  • Previous version को देखना या restore करना।
  • Multiple developers के work को manage करना।
  • Errors और unwanted changes को identify करना।
  • Project development को organized रखना।
Example: यदि website का नया version काम नहीं कर रहा है, तो version history की सहायता से पिछले stable version को identify किया जा सकता है।

3. Keeping Historical Copies

Definition

Historical Copies का अर्थ project के पुराने versions या states का record रखना है, ताकि future में changes को review, compare या recover किया जा सके।

Benefits

  • Old versions सुरक्षित रहते हैं।
  • Changes का comparison किया जा सकता है।
  • गलत changes को identify किया जा सकता है।
  • Previous working state पर वापस जाना आसान होता है।
  • Team development में accountability बढ़ती है।
Git में: Commits project के historical snapshots को record करने का मुख्य तरीका हैं।

4. Version Control and Automation

Definition

Automation का अर्थ repetitive development tasks को tools और scripts की सहायता से automatically perform करना है। Version Control systems development workflow में automation tools के साथ integrate किए जा सकते हैं।

Relationship

  • Code changes version control में record किए जाते हैं।
  • Automated tests changes को check कर सकते हैं।
  • Build और deployment processes automate किए जा सकते हैं।
  • Team को consistent development workflow मिलता है।
Code Change → Commit → Automated Check/Test → Build → Deployment
Important: Git स्वयं complete automation platform नहीं है; यह version control प्रदान करता है और automation workflows के साथ integrate किया जा सकता है।

5. What is Git?

Definition

Git एक distributed version control system है जिसका उपयोग source code और अन्य project files में होने वाले changes को track और manage करने के लिए किया जाता है।

Main Features of Git

  • Distributed Version Control
  • Change Tracking
  • Commit History
  • Branching and Merging
  • Local Repository
  • Remote Repository Support
  • Collaboration
  • Rollback/Recovery capabilities
Exam Point:
Git = Distributed Version Control System (DVCS).

6. Installing Git

Definition

Git Installation का अर्थ computer में Git software को install करना है ताकि command line या graphical tools के माध्यम से repositories और version control operations use किए जा सकें।

General Installation Process

  1. अपने operating system के लिए Git installer प्राप्त करें।
  2. Installer run करें।
  3. Installation options को requirement के अनुसार select करें।
  4. Installation complete करें।
  5. Terminal/Command Prompt खोलकर Git installation verify करें।
Check Git Version
git --version
Example Output
git version 2.x.x
Note: Exact Git version आपके installed release के अनुसार अलग हो सकती है।

7. Using Git Locally

Definition

Local Git Repository आपके computer पर मौजूद project repository होती है जिसमें Git project के files और version history को manage करता है।

Basic Local Workflow

Working Directory → Staging Area → Local Repository

Important Commands

CommandPurpose
git initCurrent folder में नया Git repository initialize करना।
git statusWorking directory और staging area की current स्थिति देखना।
git addChanges को staging area में रखना।
git commitStaged changes को repository history में record करना।
git logCommit history देखना।
Basic Git Workflow
git init git status git add . git commit -m "Initial commit" git log
Exam Point: git add changes को staging area में रखता है, जबकि git commit staged changes को repository history में record करता है।

8. Deleting and Renaming Files

Deleting a File

Git में tracked file को delete करने के लिए file को remove करके change को stage किया जा सकता है।

Delete File
git rm old-file.txt git commit -m "Remove old file"

Renaming a File

Git में tracked file का name change करने के लिए git mv command उपयोग की जा सकती है।

Rename File
git mv old-name.txt new-name.txt git commit -m "Rename file"
Exam Point: git rm tracked file को remove करने और git mv file को move/rename करने के लिए उपयोगी है।

9. Undoing Changes Before Committing

Definition

यदि किसी file में change किया गया है लेकिन अभी commit नहीं किया गया है, तो आवश्यकता के अनुसार उस change को discard या unstage किया जा सकता है।

Unstaging a File

यदि file staging area में add हो चुकी है लेकिन उसे unstage करना है, तो:

Unstage Changes
git restore --staged filename.txt

Discarding Working Directory Changes

यदि current working-tree change को discard करना हो:

Discard Uncommitted Change
git restore filename.txt
Warning: Working-directory changes discard करने पर uncommitted work खो सकता है। Command चलाने से पहले file के changes verify करें।

10. Amending Commits

Definition

Amend का अर्थ latest commit को modify करना है। इसका उपयोग latest commit में कोई additional change जोड़ने या commit message सुधारने के लिए किया जा सकता है।

Example

Amend Latest Commit
git add updated-file.txt git commit --amend -m "Updated project files"

यदि केवल latest commit message बदलना हो, तो भी git commit --amend उपयोग किया जा सकता है।

Important: Shared remote history में already-pushed commit को amend करना सावधानी से करना चाहिए, क्योंकि इससे commit history बदल सकती है।

11. Rollbacks

Definition

Rollback का अर्थ project को किसी previous known state की ओर वापस ले जाना है। Git में rollback के लिए अलग-अलग commands और approaches situation के अनुसार use की जाती हैं।

Viewing History

View Commit History
git log --oneline

Reverting a Commit

git revert एक नया commit बनाकर किसी previous commit के changes को reverse करने के लिए उपयोग किया जाता है। यह shared history के लिए generally safer approach है।

Revert a Commit
git revert <commit-id>

Reset

git reset repository के HEAD/staging/working state को अलग-अलग modes में move करने के लिए उपयोग किया जा सकता है। इसका उपयोग carefully करना चाहिए, especially shared history के साथ।

Example
git reset --soft HEAD~1
Difference: revert reverse changes के लिए नया commit बनाता है; reset current branch history/state को move कर सकता है।

12. Introduction to GitHub

Definition

GitHub एक online platform है जहाँ Git repositories को host, share और collaborate किया जा सकता है। यह developers को source code manage करने और teams के साथ collaborate करने के लिए सुविधाएँ प्रदान करता है।

Git vs GitHub

GitGitHub
Version control systemGit repository hosting/collaboration platform
Local computer पर भी use हो सकता हैOnline remote collaboration के लिए commonly used
Commits, branches आदि manage करता हैRepositories, collaboration और remote workflows provide करता है
Exam Point: Git और GitHub same चीज नहीं हैं। Git एक version control system है, जबकि GitHub Git repositories के hosting और collaboration के लिए platform है।

13. Working with Remotes

Definition

Remote Repository repository की वह copy/location है जो local computer के बाहर किसी remote server/platform पर hosted होती है। GitHub एक common remote hosting platform है।

Common Commands

Remote Commands
git remote -v git remote add origin <repository-url> git push -u origin main

Explanation

  • git remote -v configured remote URLs दिखाता है।
  • git remote add origin local repository के साथ remote repository connect करता है।
  • git push local commits को remote repository पर भेजता है।
Local Repository ⇄ Remote Repository (GitHub)

14. Fetching New Changes

Definition

Fetching का अर्थ remote repository से नए commits और references की information को local repository में लाना है, बिना current working branch में उन changes को automatically merge किए।

Fetch Remote Changes
git fetch origin

Fetch vs Pull

FetchPull
Remote changes की information download करता है।Remote changes को fetch करके current branch में integrate करने की प्रक्रिया भी करता है।
Working files को automatically update नहीं करता।Working branch update हो सकती है, depending on configuration/workflow।

15. Updating the Local Repository

Definition

Local repository को update करने का अर्थ remote repository में available latest changes को local development environment के साथ synchronize करना है।

Common Pull Workflow

Update Local Branch
git pull origin main

Basic Collaboration Workflow

git fetch → Review Changes → Integrate/Pull → Resolve Conflicts if needed → Test → Continue Development
Important: Pull करने से पहले local uncommitted changes की स्थिति check करना अच्छा practice है।

16. Best Practices for Collaboration

Important Practices

  1. Meaningful Commit Messages: Commit message में change का purpose clearly लिखें।
  2. Small Commits: Related और manageable changes को meaningful commits में record करें।
  3. Pull Before Work: Team workflow के अनुसार latest remote changes प्राप्त करें।
  4. Use Branches: Features और experiments के लिए appropriate branches use करें।
  5. Review Changes: Shared code को integrate करने से पहले changes review करें।
  6. Resolve Conflicts Carefully: Merge conflicts को समझकर correct version maintain करें।
  7. Do Not Commit Sensitive Data: Passwords, API keys और secrets repository में commit न करें।
  8. Keep Repository Organized: Unnecessary files और generated artifacts को version control में रखने से बचें।
  9. Test Before Push: Important changes को push करने से पहले test करें।
  10. Communicate with Team: Conflicting changes और major modifications के बारे में team को inform करें।
Exam Point: Effective collaboration के लिए clean commits, clear communication, regular synchronization, code review और secure repository practices important हैं।
