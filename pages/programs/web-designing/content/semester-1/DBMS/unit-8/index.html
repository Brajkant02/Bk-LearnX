1. Introduction to Database Security

Database Security का उद्देश्य database में stored information को unauthorized access, unauthorized modification, accidental loss और misuse से protect करना है। Database security में users की identity और permissions manage करने के साथ-साथ data integrity और confidentiality maintain करने के लिए कई techniques का उपयोग किया जाता है।

एक database में student records, employee information, financial data, customer details और अन्य sensitive information हो सकती है। इसलिए यह जरूरी है कि प्रत्येक user को केवल वही operations और data access मिले जिसकी उसे आवश्यकता है।

User ↓ Authentication ↓ Authorization ↓ Allowed Operations ↓ Views / Constraints / Encryption ↓ Protected Database

Database Security के मुख्य Objectives

Confidentiality

Unauthorized users को sensitive information देखने से रोकना।

Integrity

Data को accurate, valid और consistent बनाए रखना।

Availability

Authorized users को आवश्यकता के समय data उपलब्ध कराना।

Controlled Access

Users को उनके roles और responsibilities के अनुसार permissions देना।

Exam Definition: Database security is the collection of mechanisms and controls used to protect database data from unauthorized access, modification, disclosure and misuse.

2. Authorization

Authorization वह process है जिसमें यह निर्धारित किया जाता है कि authenticated user database में कौन-कौन से resources और operations access कर सकता है। इसमें user को privileges या permissions प्रदान की जाती हैं।

उदाहरण के लिए, एक college database में administrator को student records insert, update और delete करने की permission हो सकती है, जबकि सामान्य teacher को केवल student information देखने की permission दी जा सकती है।

Authorization और Authentication में अंतर

Authentication Authorization
User की identity verify करता है। Verified user की permissions determine करता है।
Question: “आप कौन हैं?” Question: “आप क्या कर सकते हैं?”
Login/password आदि से associated। Privileges, roles और access rules से associated।

Database Privileges

Common database privileges में SELECT, INSERT, UPDATE, DELETE और कुछ systems में EXECUTE जैसे privileges शामिल हो सकते हैं।

GRANT

GRANT command के द्वारा authorized user या role को privilege दिया जा सकता है।

GRANT SELECT ON Student TO teacher1;

ऊपर example में teacher1 को Student object पर SELECT privilege देने का उद्देश्य दिखाया गया है।

Multiple Privileges

GRANT SELECT, INSERT, UPDATE ON Student TO teacher1;

REVOKE

REVOKE command के द्वारा पहले दिए गए privilege को वापस लिया जा सकता है।

REVOKE INSERT ON Student FROM teacher1;
Remember: GRANT = Permission देना   |   REVOKE = Permission वापस लेना

3. Security Through Views

View एक virtual table-like representation है जो एक SQL query पर based होती है। Views का उपयोग केवल convenience के लिए नहीं बल्कि database security में भी किया जा सकता है। View के द्वारा user को पूरी table की बजाय required rows या columns का limited subset दिखाया जा सकता है।

Example: Employee Table

Employee ------------------------------------------ EmpID | Name | Salary | Department | Phone

मान लीजिए सामान्य employee को salary और phone information नहीं दिखानी है। इसके लिए limited columns वाली view बनाई जा सकती है।

CREATE VIEW Employee_Public AS SELECT EmpID, Name, Department FROM Employee;

अब authorized user को:

SELECT * FROM Employee_Public;

से केवल selected columns दिखाई जा सकती हैं। इस तरह view sensitive columns की direct exposure कम करने में सहायता कर सकती है।

Row-Level Restriction Example

View के द्वारा rows भी filter की जा सकती हैं।

CREATE VIEW PGDCA_Students AS SELECT StudentID, Name, Course FROM Student WHERE Course = 'PGDCA';

इस view के माध्यम से केवल PGDCA course के students का selected data expose किया जा सकता है।

Views के Security Benefits

  • Sensitive columns को hide करने में सहायता।
  • Specific rows तक access limit करने में सहायता।
  • Users को simplified interface देना।
  • Underlying tables का direct access कम करने में सहायता।
  • Role-based data exposure implement करने में useful।
Important: View security का एक layer है। केवल view बनाना complete database security solution नहीं है; privileges और अन्य security controls भी properly configure करने चाहिए।

4. Security Constraints

Security constraints वे rules और controls हैं जो database resources तक access को restrict और regulate करते हैं। इनका उद्देश्य यह सुनिश्चित करना है कि केवल authorized users ही specified data या operations perform कर सकें।

मुख्य Security Controls

Control Purpose
Authentication User की identity verify करना।
Authorization User की permissions define करना।
Privileges Specific operations जैसे SELECT/INSERT आदि को control करना।
Roles Multiple privileges को logical group में manage करना।
Views Users को selected rows/columns expose करना।
Encryption Data को protected form में encode करना।
Auditing Database activities और access events को track करने में सहायता।

Role-Based Authorization

बड़े systems में individual users को अलग-अलग privileges देने के बजाय roles बनाकर permissions manage करना आसान हो सकता है।

User ↓ Role ↓ Privileges ↓ Database Objects

उदाहरण: Teacher role को Student table पर SELECT privilege दिया जा सकता है, जबकि Admin role को SELECT, INSERT, UPDATE और DELETE जैसे additional privileges दिए जा सकते हैं।

Principle of Least Privilege

Least Privilege का अर्थ है user को केवल उतनी permissions देना जितनी उसके काम के लिए आवश्यक हैं। इससे unauthorized modification या accidental misuse का risk कम करने में सहायता मिलती है।

Exam Point: Security constraints access control को enforce करते हैं ताकि unauthorized users database resources को freely access या modify न कर सकें।

5. Integrity Constraints

Integrity Constraints database में data की correctness, validity और consistency बनाए रखने के लिए लगाए गए rules हैं। ये ensure करते हैं कि invalid या logically inconsistent data database में enter न हो।

Integrity और Security का संबंध

Security मुख्यतः यह control करती है कि कौन data access या modify कर सकता है, जबकि integrity constraints यह control करते हैं कि database में किस प्रकार का valid data store किया जा सकता है।

Major Integrity Constraints

Constraint Purpose Example
NOT NULL Column में NULL value को prevent करता है। Name VARCHAR(50) NOT NULL
UNIQUE Duplicate values को restrict करता है। Email VARCHAR(100) UNIQUE
PRIMARY KEY प्रत्येक row को uniquely identify करता है। StudentID INT PRIMARY KEY
FOREIGN KEY Related tables के बीच referential integrity maintain करता है। FOREIGN KEY (DeptID) REFERENCES Department(DeptID)
CHECK Column values पर condition enforce करता है। Age INT CHECK (Age >= 18)
DEFAULT Value न दिए जाने पर default value provide करता है। Status VARCHAR(20) DEFAULT 'Active'

Primary Key Example

CREATE TABLE Student ( StudentID INT PRIMARY KEY, Name VARCHAR(50) NOT NULL );

StudentID को primary key बनाने से प्रत्येक student record की unique identification maintain करने में सहायता मिलती है।

Foreign Key Example

CREATE TABLE Department ( DeptID INT PRIMARY KEY, DeptName VARCHAR(50) ); CREATE TABLE Employee ( EmpID INT PRIMARY KEY, Name VARCHAR(50), DeptID INT, FOREIGN KEY (DeptID) REFERENCES Department(DeptID) );

Foreign key यह ensure करने में सहायता करती है कि Employee में दिया गया DeptID referenced Department table में valid department को refer करे।

CHECK Constraint Example

CREATE TABLE Employee ( EmpID INT PRIMARY KEY, Age INT CHECK (Age >= 18) );

इससे age के लिए specified condition enforce की जा सकती है।

Types of Integrity

Entity Integrity

Primary key unique और appropriate identification provide करे तथा key value NULL न हो।

Referential Integrity

Foreign key relationships को valid referenced records के साथ consistent रखना।

Domain Integrity

Column में valid data type और allowed value range/condition maintain करना।

User-Defined Integrity

Application-specific business rules को enforce करना।

6. Encryption

Encryption एक security technique है जिसमें readable data (plaintext) को algorithm और key की सहायता से ऐसी protected form (ciphertext) में transform किया जाता है जिसे unauthorized person के लिए समझना कठिन हो।

Plaintext ↓ Encryption Algorithm + Key ↓ Ciphertext ↓ Decryption + Key ↓ Plaintext

Example Concept

Plaintext: "Student Data" ↓ Encryption Ciphertext: "Encrypted / Protected Data" ↓ Decryption Plaintext: "Student Data"

Real encryption में ciphertext algorithm और cryptographic key के आधार पर generate होता है। ऊपर केवल concept समझाने के लिए simplified representation है।

Encryption के प्रमुख Types

1. Symmetric Encryption

Symmetric encryption में encryption और decryption के लिए same secret key का उपयोग होता है। इसलिए sender और receiver को key securely share/manage करनी होती है।

Same Secret Key ↓ ↑ Plaintext → Encryption → Ciphertext Ciphertext → Decryption → Plaintext

Symmetric encryption large amounts of data को efficiently protect करने के लिए commonly used approach है।

2. Asymmetric Encryption

Asymmetric encryption में key pair होता है: public key और private key। दोनों keys का अलग-अलग role होता है।

Public Key → Encryption Private Key → Decryption

Asymmetric cryptography secure communication और key exchange जैसे use cases में important भूमिका निभाती है।

Encryption at Rest

जब database files या stored data disk/storage पर पड़ा होता है, उस data को protect करने के लिए encryption-at-rest techniques का उपयोग किया जा सकता है।

Encryption in Transit

जब data network के माध्यम से application और database के बीच travel कर रहा हो, तो secure communication mechanisms के द्वारा उसे protect किया जा सकता है।

Encryption के Benefits

  • Sensitive data की confidentiality बढ़ती है।
  • Unauthorized disclosure का risk कम करने में सहायता।
  • Stored data और transmitted data को protect किया जा सकता है।
  • Security और privacy requirements को support किया जा सकता है।
Important: Encryption access control का replacement नहीं है। Strong database security के लिए authorization, least privilege, integrity controls और encryption जैसे multiple layers को appropriately combine करना चाहिए।

8. Database Security Workflow

Example Scenario

मान लीजिए एक college database में Student और Employee information stored है। एक secure design में अलग-अलग security mechanisms को combine किया जा सकता है।

  1. User पहले authenticate होता है।
  2. User को उसके role के आधार पर authorization दी जाती है।
  3. View के माध्यम से केवल required columns/rows expose किए जाते हैं।
  4. Integrity constraints invalid data को रोकते हैं।
  5. Sensitive stored/transmitted data को encryption से protect किया जा सकता है।
  6. Least privilege principle के अनुसार unnecessary permissions नहीं दी जातीं।
-- Example: Limited view CREATE VIEW Student_Public AS SELECT StudentID, Name, Course FROM Student; -- Example: Access permission GRANT SELECT ON Student_Public TO teacher1;

इस design में teacher को complete Student table की बजाय public view का access दिया जा सकता है। यह example concept demonstration के लिए है; actual DBMS में privilege syntax और security architecture product-specific हो सकते हैं।

Conclusion

Database security एक single technique पर depend नहीं करती। Authorization यह control करता है कि user क्या access कर सकता है, views selected data expose करने में मदद करते हैं, integrity constraints data को valid और consistent रखने में सहायता करते हैं, जबकि encryption sensitive information की confidentiality protect करने में महत्वपूर्ण भूमिका निभाती है। इन controls को सही तरीके से combine करके एक मजबूत database security architecture बनाया जा सकता है।
