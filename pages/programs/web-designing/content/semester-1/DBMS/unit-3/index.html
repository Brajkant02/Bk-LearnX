Relational Model

Introduction to Relational Model

Relational Model database में data को tables के रूप में organize करता है। प्रत्येक table को relation कहा जाता है, प्रत्येक row को tuple और प्रत्येक column को attribute कहा जाता है। यह model simple, flexible और widely used है क्योंकि users data को rows और columns के रूप में आसानी से समझ सकते हैं।

Image Placeholder: Relational Model Overview

Main Features

  • Data tables में stored होता है।
  • Rows unique records represent करती हैं।
  • Columns properties represent करती हैं।
  • Keys tables के बीच relationship establish करती हैं।
  • SQL के द्वारा data manipulate किया जाता है।
Remember:
Relational Model में table को relation, row को tuple और column को attribute कहा जाता है।

Advantages of Relational Model

  • Simple tabular structure।
  • Data access और querying आसान।
  • Data redundancy कम की जा सकती है।
  • Integrity constraints support करता है।
  • Security और user permissions implement करना आसान।
  • Backup, recovery और transaction management support।
  • SQL जैसी standard language available।
  • Data independence improve होती है।
Real Life Example:
Student, Course और Enrollment को अलग tables में store करके duplicate data कम किया जा सकता है।

Disadvantages of Relational Model

  • Very complex hierarchical या graph data के लिए multiple joins required हो सकते हैं।
  • Large-scale joins performance slow कर सकते हैं।
  • Object-oriented data directly represent करना difficult हो सकता है।
  • Schema changes large applications में costly हो सकती हैं।
  • Distributed unstructured data के लिए हमेशा best option नहीं।

Codd's Rules - Introduction

Dr. E. F. Codd ने relational database systems को define करने के लिए rules propose किए। इन्हें commonly Codd's 12 Rules कहा जाता है, लेकिन numbering Rule 0 से Rule 12 तक होती है।

Image Placeholder: Codd's Rules Overview

Codd's 12 Rules

Rule Name Simple Meaning
Rule 0 Foundation Rule System relational capabilities से database manage करे।
Rule 1 Information Rule All information tables में values के रूप में store हो।
Rule 2 Guaranteed Access हर value table, key और column से accessible हो।
Rule 3 Systematic Null Treatment Missing/unknown values consistently handle हों।
Rule 4 Dynamic Online Catalog Metadata भी relational form में accessible हो।
Rule 5 Comprehensive Data Language एक language data definition, manipulation, security और transactions support करे।
Rule 6 View Updating Theoretically updateable views update की जा सकें।
Rule 7 High-Level Insert, Update, Delete Set-level operations support हों।
Rule 8 Physical Data Independence Storage changes applications को affect न करें।
Rule 9 Logical Data Independence Logical changes applications पर minimum effect डालें।
Rule 10 Integrity Independence Constraints database catalog में defined हों।
Rule 11 Distribution Independence Data location users के लिए transparent हो।
Rule 12 Non-Subversion Rule Low-level access integrity rules bypass न करे।

Relation

Relation rows और columns से बनी table है। Relation का unique name होता है और प्रत्येक cell में atomic value होनी चाहिए।

Properties of Relation

  • Duplicate tuples नहीं होने चाहिए।
  • Rows का order important नहीं।
  • Columns का order logical meaning नहीं बदलता।
  • हर attribute का unique name होता है।
  • हर column का domain defined होता है।

Tuple, Attribute, Degree and Cardinality

Term Meaning Example
Tuple Table की एक row एक student record
Attribute Table का column Name, Roll_No
Degree Attributes की संख्या 4 columns = degree 4
Cardinality Tuples की संख्या 100 rows = cardinality 100

Image Placeholder: Relation Terminology

Schema

Schema database या relation की logical design होती है। इसमें table name, attributes, data types, keys और constraints define होते हैं।

STUDENT(Student_ID, Name, Course, Email)

यह STUDENT relation का schema है।

Sub Schema

Sub Schema database का user-specific view होता है। अलग users को database का अलग portion दिखाई दे सकता है।

Example

  • Teacher को student marks दिखाई दें।
  • Account department को fee details दिखाई दें।
  • Student को केवल अपना profile और result दिखाई दे।
Remember:
Schema complete database design है, जबकि subschema user-specific view है।

Relational Constraints

Relational Constraints वे rules हैं जो database data को valid, accurate और consistent बनाए रखते हैं। Constraints गलत, duplicate या incomplete data को prevent करती हैं।

Image Placeholder: Relational Constraints Overview

Domain Constraint

Domain Constraint define करती है कि किसी attribute में किस type और range की values store हो सकती हैं।

Examples

  • Age integer और positive हो।
  • Email text format में हो।
  • Marks 0 से 100 के बीच हों।
  • Gender predefined values में हो।
Marks INT CHECK (Marks BETWEEN 0 AND 100)

Tuple Uniqueness Constraint

Relation में duplicate tuples नहीं होने चाहिए। प्रत्येक row किसी unique real-world record को represent करे। Primary key और candidate keys tuple uniqueness enforce करने में help करती हैं।

Example:
दो students का Student_ID same नहीं हो सकता।

Key Constraints

Attributes का कोई भी set जो tuple को uniquely identify करे।

Candidate Key

Minimal super key।

Primary Key

Selected candidate key।

Alternate Key

Candidate key जो primary key select नहीं हुई।

Foreign Key

एक relation का attribute जो दूसरे relation की primary key refer करता है।

Integrity Constraints

Integrity constraints database consistency maintain करती हैं। Main types entity integrity और referential integrity हैं।

Constraint Purpose
Entity Integrity Primary key null नहीं हो सकती।
Referential Integrity Foreign key valid referenced value रखे।
Domain Integrity Values valid domain से हों।
User-defined Integrity Business-specific rules।

Entity Integrity Constraint

Entity Integrity के अनुसार primary key की value null नहीं हो सकती, क्योंकि primary key प्रत्येक tuple को uniquely identify करती है।

Example

Student_ID INT PRIMARY KEY

Student_ID missing होने पर student record uniquely identify नहीं होगा।

Referential Integrity Constraint

Referential Integrity ensure करती है कि foreign key की value referenced table की primary key में exist करे या allowed होने पर null हो।

Image Placeholder: Referential Integrity between Tables

Example

DEPARTMENT(Dept_ID, Dept_Name)
STUDENT(Student_ID, Name, Dept_ID)

STUDENT.Dept_ID में वही value होनी चाहिए जो DEPARTMENT.Dept_ID में मौजूद हो।

Constraint Violation Examples

Referential Actions

Referenced row update या delete होने पर DBMS different actions perform कर सकता है।

Action Meaning
CASCADE Related child rows भी update/delete हों।
SET NULL Foreign key null हो जाए।
SET DEFAULT Default value set हो।
RESTRICT / NO ACTION Referenced row change prevent हो।
Remember:
Constraints database में केवल errors रोकती नहीं, बल्कि business rules enforce करती हैं।

Relational Algebra

Relational Algebra procedural query language है जिसमें relations पर operations perform करके new relation generate किया जाता है। यह SQL की theoretical foundation है।

Image Placeholder: Relational Algebra Overview

Basic Principle

हर relational algebra operation का input relation होता है और output भी relation होता है। इसे closure property कहा जाता है।

Union Operation

Union दो union-compatible relations के सभी tuples combine करता है और duplicates remove करता है।

R ∪ S

Conditions

  • Same number of attributes।
  • Corresponding attributes compatible domains के हों।

Image Placeholder: Relational Algebra Union

Intersection Operation

Intersection केवल वे tuples return करता है जो दोनों relations में common हों।

R ∩ S

Difference Operation

Difference R के वे tuples return करता है जो S में नहीं हैं।

R − S

Important

R − S और S − R generally different results देते हैं।

Cartesian Product

Cartesian Product R की हर row को S की हर row के साथ combine करता है।

R × S

यदि R में m tuples और S में n tuples हैं, तो result में m × n tuples होंगे।

Image Placeholder: Cartesian Product

Selection Operation

Selection condition के आधार पर rows select करता है। इसे horizontal subset भी कहा जाता है। 

σ Marks > 60 (STUDENT)

यह उन students को select करेगा जिनके marks 60 से अधिक हैं।

Projection Operation

Projection required columns select करता है। इसे vertical subset कहा जाता है। Duplicate rows remove हो सकती हैं।

π Name, Course (STUDENT)

Rename Operation

Rename relation या attributes का temporary name change करता है।

ρ S(Student_ID, Student_Name) (STUDENT)

Complex expressions और self-join में rename useful है।

Join Operation

Join related attributes के आधार पर two relations combine करता है।

Image Placeholder: Join between Student and Department

Join Type Meaning
Theta Join Any comparison condition use करता है।
Equi Join Equality condition use करता है।
Natural Join Same-name attributes automatically match करता है।
Outer Join Unmatched rows भी preserve कर सकता है।

Division Operation

Division उन entities को find करने के लिए use होता है जो related set की सभी values से related हों।

Example

उन students को find करना जिन्होंने सभी compulsory courses complete किए हैं।

Remember:
Division “for all” type queries के लिए useful है।

Converting ER Model to Relational Model

ER model को relational tables में convert करने के लिए entities, attributes और relationships को systematic rules के अनुसार map किया जाता है।

Image Placeholder: ER Model to Relational Tables

Strong Entity

Each strong entity के लिए separate table बनाएं और key attribute को primary key बनाएं।

Weak Entity

Weak entity table में owner entity की primary key include करें। Owner key + partial key composite primary key बन सकती है।

One-to-One Relationship

Foreign key किसी एक suitable table में add करें।

One-to-Many Relationship

One-side की primary key many-side table में foreign key बनती है।

Many-to-Many Relationship

Separate relationship table बनाएं जिसमें दोनों entities की keys foreign keys हों।

Mapping Attributes

Attribute Type Relational Conversion
Simple Direct column
Composite Components as separate columns
Multi-valued Separate table
Derived Usually calculate, store only if needed

Common Mistakes and Best Practices

Common Mistakes

  • Union compatibility ignore करना।
  • Selection और projection confuse करना।
  • Join condition miss करना जिससे unwanted Cartesian product बन जाए।
  • Many-to-many relationship के लिए separate table न बनाना।
  • Foreign key constraints ignore करना।

Best Practices

  • Relations और attributes के clear names रखें।
  • Primary keys carefully select करें।
  • Relational algebra expression step-by-step solve करें।
  • ER conversion के बाद redundancy और constraints verify करें।
Remember:
Relational Algebra query logic समझाती है और ER-to-Relational conversion database implementation की foundation बनाती है।
