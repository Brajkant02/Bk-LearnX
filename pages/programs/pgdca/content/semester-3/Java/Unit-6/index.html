Polymorphism

Polymorphism

Polymorphism object-oriented programming का एक important concept है। Polymorphism का meaning है many forms. Java में polymorphism का मतलब है कि same method name, same object reference या same operation different situations में different behavior show कर सकता है। इससे program flexible, reusable और maintainable बनता है।

Java में polymorphism mainly two types का होता है: compile-time polymorphism और runtime polymorphism. Compile-time polymorphism method overloading और constructor overloading से achieve होता है। Runtime polymorphism method overriding और dynamic method dispatch से achieve होता है।

Types of Polymorphism

Type Achieved By Decision Time
Compile-time Polymorphism Method Overloading, Constructor Overloading Compile time
Runtime Polymorphism Method Overriding Runtime

Simple Real Life Idea

एक word “draw” अलग-अलग objects के लिए different behavior show कर सकता है। Circle draw करे तो circle बनेगा, Rectangle draw करे तो rectangle बनेगा और Triangle draw करे तो triangle बनेगा। Same action name है, लेकिन behavior object के according change हो रहा है। यही polymorphism का basic idea है।

Benefits of Polymorphism

  • Code flexibility बढ़ती है।
  • Same method name से multiple tasks perform किए जा सकते हैं।
  • Runtime पर correct method call हो सकता है।
  • Parent reference से child objects handle किए जा सकते हैं।
  • Large applications में code maintain करना easier होता है।
Remember:
Polymorphism same name या same reference को different forms में behavior देने की ability है।

Method Overloading

Method overloading Java में compile-time polymorphism का example है। जब एक ही class में same method name के multiple methods हों, लेकिन उनके parameters अलग हों, तो उसे method overloading कहते हैं। Parameters की संख्या, type या order different हो सकता है।

Method overloading से same task के related methods को same name दिया जा सकता है। इससे code readable बनता है। For example, calculator में add method two integers, three integers या decimal values को add कर सकता है।

Image Placeholder: Method Overloading Diagram

Rules of Method Overloading

  • Method name same होना चाहिए।
  • Parameter list different होनी चाहिए।
  • Parameter number, type या order change हो सकता है।
  • Only return type change करने से overloading नहीं होती।
  • Method overloading same class में या inherited class में हो सकती है।

Overloading by Number of Parameters

class Calculator {
    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }

    public static void main(String[] args) {
        Calculator c = new Calculator();

        System.out.println(c.add(10, 20));
        System.out.println(c.add(10, 20, 30));
    }
}
Output:
30
60

Overloading by Type of Parameters

class Calculator {
    int add(int a, int b) {
        return a + b;
    }

    double add(double a, double b) {
        return a + b;
    }

    public static void main(String[] args) {
        Calculator c = new Calculator();

        System.out.println(c.add(5, 7));
        System.out.println(c.add(5.5, 7.2));
    }
}
Output:
12
12.7

Overloading by Order of Parameters

class Display {
    void show(String name, int age) {
        System.out.println(name + " " + age);
    }

    void show(int age, String name) {
        System.out.println(age + " " + name);
    }

    public static void main(String[] args) {
        Display d = new Display();

        d.show("Brajkant", 23);
        d.show(23, "Brajkant");
    }
}
Output:
Brajkant 23
23 Brajkant

class Test {
    int show(int a) {

Advantages

  • Same logical task के लिए same method name use होता है।
  • Program readability improve होती है।
  • Compile-time polymorphism achieve होता है।
  • Code clean और organized लगता है।
Real Life Example:
Print command text, image या document को print कर सकती है। Method name same हो सकता है, लेकिन input type के according काम different हो सकता है।
Remember:
Method overloading में method name same और parameter list different होती है।

Constructor Overloading

Constructor overloading तब होती है जब एक class में multiple constructors हों और उनके parameter lists different हों। Constructor overloading का use objects को different ways से initialize करने के लिए किया जाता है।

Constructor का name class name के same होता है और इसका return type नहीं होता। Constructor overloading compile-time polymorphism का example है क्योंकि compiler parameter list देखकर decide करता है कि कौन-सा constructor call होगा।

Image Placeholder: Constructor Overloading Diagram

Example

class Student {
    String name;
    int roll;

    Student() {
        name = "Unknown";
        roll = 0;
    }

    Student(String n) {
        name = n;
        roll = 0;
    }

    Student(String n, int r) {
        name = n;
        roll = r;
    }

    void display() {
        System.out.println(name + " " + roll);
    }

    public static void main(String[] args) {
        Student s1 = new Student();
        Student s2 = new Student("Brajkant");
        Student s3 = new Student("Amit", 102);

        s1.display();
        s2.display();
        s3.display();
    }
}
Output:
Unknown 0
Brajkant 0
Amit 102

Why Constructor Overloading is Used

  • Object को different initial values के साथ create करने के लिए।
  • Default values और custom values दोनों support करने के लिए।
  • Flexible object creation के लिए।
  • Code readability improve करने के लिए।

Constructor Chaining with this()

class Student {
    String name;
    int roll;

    Student() {
        this("Unknown", 0);
    }

    Student(String name, int roll) {
        this.name = name;
        this.roll = roll;
    }

    void display() {
        System.out.println(name + " " + roll);
    }

    public static void main(String[] args) {
        Student s = new Student();
        s.display();
    }
}
Output:
Unknown 0

Calling Object creation पर call होता है। Manually call किया जाता है।

Remember:
Constructor overloading object को multiple ways से initialize करने की facility देता है।

Method Overriding

Method overriding Java में runtime polymorphism का important concept है। जब child class parent class के method को same name, same return type और same parameters के साथ फिर से define करती है, तो इसे method overriding कहते हैं।

Overriding का use तब होता है जब parent class का method child class के लिए suitable नहीं है और child class अपना specific implementation देना चाहती है। Runtime पर object के actual type के according method call होता है।

Image Placeholder: Method Overriding Diagram

Example

class Animal {
    void sound() {
        System.out.println("Animal makes sound");
    }
}

class Dog extends Animal {
    void sound() {
        System.out.println("Dog barks");
    }

    public static void main(String[] args) {
        Dog d = new Dog();
        d.sound();
    }
}
Output:
Dog barks

Rules of Method Overriding

  • Inheritance relationship होना चाहिए।
  • Method name same होना चाहिए।
  • Parameter list same होनी चाहिए।
  • Return type same या covariant हो सकता है।
  • Access modifier parent method से more restrictive नहीं हो सकता।
  • Static methods override नहीं होते, वे hide होते हैं।
  • Final method override नहीं किया जा सकता।
  • Private method override नहीं होता क्योंकि वह child class में accessible नहीं है।

Using @Override Annotation

class Animal {
    void sound() {
        System.out.println("Animal sound");
    }
}

class Cat extends Animal {
    @Override
    void sound() {
        System.out.println("Cat meows");
    }
}

@Override annotation compiler को बताता है कि यह method parent method को override कर रहा है। अगर method signature गलत हो, तो compiler error देता है।

Overriding with Parent Reference

class Animal {
    void sound() {
        System.out.println("Animal sound");
    }
}

class Dog extends Animal {
    void sound() {
        System.out.println("Dog barks");
    }
}

class Main {
    public static void main(String[] args) {
        Animal a = new Dog();
        a.sound();
    }
}
Output:
Dog barks

super Keyword in Overriding

super keyword से child class parent class के overridden method को call कर सकती है।

class Animal {
    void sound() {
        System.out.println("Animal sound");
    }
}

class Dog extends Animal {
    void sound() {
        super.sound();
        System.out.println("Dog barks");
    }

    public static void main(String[] args) {
        Dog d = new Dog();
        d.sound();
    }
}
Output:
Animal sound
Dog barks
Real Life Example:
Vehicle class में start() method हो सकता है। Bike और Car classes उसी method को अपने तरीके से override कर सकती हैं।
Remember:
Method overriding में parent और child class में same method signature होता है।

Method Overloading vs Method Overriding

Method overloading और method overriding दोनों polymorphism से related हैं, लेकिन दोनों का purpose और working different है। Overloading same class में same method name के multiple forms देता है, जबकि overriding child class को parent method का new implementation देने की facility देता है।

Runtime Polymorphism and Dynamic Method Dispatch

Runtime polymorphism वह process है जिसमें method call runtime पर object के actual type के according decide होता है। Java में यह method overriding और parent class reference के through achieve होता है। इसे dynamic method dispatch भी कहा जाता है।

जब parent class reference child class object को refer करता है और overridden method call होता है, तो Java runtime पर decide करती है कि child class वाला method execute होगा।

Image Placeholder: Dynamic Method Dispatch Diagram

Example

class Shape {
    void draw() {
        System.out.println("Drawing shape");
    }
}

class Circle extends Shape {
    void draw() {
        System.out.println("Drawing circle");
    }
}

class Rectangle extends Shape {
    void draw() {
        System.out.println("Drawing rectangle");
    }
}

class Main {
    public static void main(String[] args) {
        Shape s;

        s = new Circle();
        s.draw();

        s = new Rectangle();
        s.draw();
    }
}
Output:
Drawing circle
Drawing rectangle

Explanation

यहाँ reference variable s का type Shape है, लेकिन runtime पर यह पहले Circle object और फिर Rectangle object को refer कर रहा है। इसलिए draw() method का behavior object के according change हो रहा है।

Benefits

  • Flexible code design possible होता है।
  • Parent reference से multiple child objects handle किए जा सकते हैं।
  • Runtime पर correct method execute होता है।
  • Extensible applications बनाना आसान होता है।
Real Life Example:
Payment reference UPI, Card या NetBanking object को refer कर सकता है और pay() method हर object के according अलग behavior show कर सकता है।
Remember:
Runtime polymorphism में method call object के actual type पर depend करता है, reference type पर नहीं।

Up-casting

Up-casting वह process है जिसमें child class object को parent class reference में store किया जाता है। Java में up-casting automatically हो सकती है क्योंकि child object parent type का भी होता है। इसे safe casting माना जाता है।

Up-casting runtime polymorphism में बहुत important है। Parent reference child object को refer कर सकता है और overridden methods runtime पर child class के according execute हो सकते हैं।

Image Placeholder: Up-casting Diagram

Syntax

Parent reference = new Child();

Example

class Animal {
    void eat() {
        System.out.println("Animal eats");
    }
}

class Dog extends Animal {
    void bark() {
        System.out.println("Dog barks");
    }
}

class Main {
    public static void main(String[] args) {
        Animal a = new Dog();   // Up-casting

        a.eat();
        // a.bark(); // Error
    }
}
Output:
Animal eats

Important Point

Up-casted reference parent class के members को access कर सकता है। Child class के special methods direct access नहीं हो सकते, unless वे parent में declared/overridden हों।

Up-casting with Overriding

class Animal {
    void sound() {
        System.out.println("Animal sound");
    }
}

class Dog extends Animal {
    void sound() {
        System.out.println("Dog barks");
    }
}

class Main {
    public static void main(String[] args) {
        Animal a = new Dog();

        a.sound();
    }
}
Output:
Dog barks

Why Up-casting is Used

  • Runtime polymorphism achieve करने के लिए।
  • Parent reference से multiple child objects handle करने के लिए।
  • Flexible और generalized code लिखने के लिए।
  • Collections और method arguments में parent type use करने के लिए।

Example with Method Argument

class Animal {
    void sound() {
        System.out.println("Animal sound");
    }
}

class Dog extends Animal {
    void sound() {
        System.out.println("Dog barks");
    }
}

class Cat extends Animal {
    void sound() {
        System.out.println("Cat meows");
    }
}

class Main {
    static void makeSound(Animal a) {
        a.sound();
    }

    public static void main(String[] args) {
        makeSound(new Dog());
        makeSound(new Cat());
    }
}
Output:
Dog barks
Cat meows
Remember:
Up-casting child object को parent reference में store करना है और यह automatically safe होता है।

Down-casting

Down-casting वह process है जिसमें parent class reference को child class reference में convert किया जाता है। Down-casting manually करनी पड़ती है और यह तभी safe होती है जब parent reference actually child object को refer कर रहा हो। गलत down-casting से ClassCastException आ सकता है।

Down-casting का use तब किया जाता है जब up-casted reference से child class के special methods access करने हों। Parent reference normally child-specific methods access नहीं कर सकता।

Image Placeholder: Down-casting Diagram

Syntax

Child childRef = (Child) parentRef;

Example

class Animal {
    void eat() {
        System.out.println("Animal eats");
    }
}

class Dog extends Animal {
    void bark() {
        System.out.println("Dog barks");
    }
}

class Main {
    public static void main(String[] args) {
        Animal a = new Dog();   // Up-casting

        Dog d = (Dog) a;        // Down-casting

        d.eat();
        d.bark();
    }
}
Output:
Animal eats
Dog barks

Wrong Down-casting

class Animal { }

class Dog extends Animal { }

class Cat extends Animal { }

class Main {
    public static void main(String[] args) {
        Animal a = new Cat();

        // Dog d = (Dog) a; // Runtime error: ClassCastException
    }
}

Using instanceof Before Down-casting

instanceof operator check करता है कि object किसी particular class का instance है या नहीं। Down-casting से पहले इसका use safe practice है।

class Animal { }

class Dog extends Animal {
    void bark() {
        System.out.println("Dog barks");
    }
}

class Main {
    public static void main(String[] args) {
        Animal a = new Dog();

        if (a instanceof Dog) {
            Dog d = (Dog) a;
            d.bark();
        }
    }
}
Output:
Dog barks

Basis Up-casting Down-casting
Direction Child to Parent Parent to Child

Safety Generally safe Risky if object type wrong

Example Animal a = new Dog(); Dog d = (Dog) a;
Real Life Example:
Animal reference से general animal behavior access होगा, लेकिन अगर actual object Dog है और bark() call करना है, तो Dog में down-cast करना पड़ेगा।
Remember:
Down-casting से पहले instanceof use करना safe practice है।

Overriding Restrictions

Java में हर method override नहीं किया जा सकता। कुछ methods जैसे final, static और private methods overriding के normal rules follow नहीं करते। इन restrictions को समझना important है क्योंकि exam में अक्सर पूछा जाता है कि कौन-से methods override हो सकते हैं और कौन-से नहीं।

Final Method Cannot Be Overridden

class Parent {
    final void show() {
        System.out.println("Final method");
    }
}

class Child extends Parent {
    // void show() { } // Error
}

final method को child class override नहीं कर सकती।

Static Method is Hidden, Not Overridden

class Parent {
    static void show() {
        System.out.println("Parent static method");
    }
}

class Child extends Parent {
    static void show() {
        System.out.println("Child static method");
    }
}

class Main {
    public static void main(String[] args) {
        Parent p = new Child();
        p.show();
    }
}
Output:
Parent static method

Static methods class से belong करते हैं, object से नहीं। इसलिए इन्हें override नहीं माना जाता; इसे method hiding कहा जाता है।

Private Method is Not Overridden

class Parent {
    private void show() {
        System.out.println("Parent private method");
    }
}

class Child extends Parent {
    void show() {
        System.out.println("Child method");
    }
}

Private method parent class के बाहर accessible नहीं होता, इसलिए child class वाला method new method माना जाएगा, overriding नहीं।

Restriction Table

Method Type Override Possible? Reason
Final Method No Final method change नहीं किया जा सकता।
Static Method No Method hiding होती है, overriding नहीं।
Private Method No Child class में accessible नहीं होता।
Public/Protected Method Yes Inherited और accessible होते हैं।
Remember:
Final method override नहीं होता, static method hide होता है और private method inherit होकर direct override नहीं होता।
