Multithreading

Introduction to Multithreading

Multithreading Java का एक powerful feature है जिसकी help से एक program के अंदर multiple threads एक साथ execute हो सकते हैं। Thread program execution की smallest unit होती है। Simple words में, thread एक lightweight process की तरह होता है जो किसी specific task को perform करता है।

Java में multithreading का use तब किया जाता है जब हमें एक application में multiple tasks simultaneously perform कराने हों। For example, एक media player में music play होना, progress bar update होना और user controls respond करना, ये सभी tasks अलग-अलग threads द्वारा handle किए जा सकते हैं।

Multithreading program की performance और responsiveness improve कर सकता है। अगर एक task time ले रहा है, तो दूसरा task wait किए बिना run हो सकता है। Java में thread support built-in है और java.lang.Thread class तथा Runnable interface की help से threads create किए जा सकते हैं।

Why Multithreading is Needed

  • Multiple tasks को parallel-like manner में perform करने के लिए।
  • Program responsiveness improve करने के लिए।
  • CPU utilization better करने के लिए।
  • Time-consuming tasks को background में run करने के लिए।
  • Real-time applications को smooth बनाने के लिए।

Simple Real Life Example

मान लो आप mobile पर song सुन रहे हैं और साथ में file download भी हो रही है। Song play होना और file download होना दो different tasks हैं। ये tasks एक ही application या system में simultaneously चल सकते हैं। यही multithreading का practical feel है।

Process vs Thread

Process एक running program होता है। जब कोई program memory में load होकर execute होता है, तो उसे process कहा जाता है। For example, browser, music player और text editor अलग-अलग processes हो सकते हैं। हर process के पास अपनी separate memory और resources होते हैं।

Thread process के अंदर execution की छोटी unit होती है। एक process के अंदर multiple threads हो सकते हैं। Threads same process की memory और resources share करते हैं, इसलिए threads को lightweight माना जाता है।

Process Example

अगर आपके computer में Chrome browser open है, तो वह एक process हो सकता है। Chrome के अंदर अलग-अलग tabs, download manager और rendering tasks अलग-अलग threads की तरह work कर सकते हैं।

Thread Example

एक Java application में एक thread user input handle कर सकता है, दूसरा calculation कर सकता है और तीसरा data save कर सकता है। ये सभी threads same application process के अंदर run हो सकते हैं।

Difference between Multitasking and Multithreading

Multitasking का मतलब है एक system द्वारा multiple tasks को एक साथ manage करना। इसमें operating system multiple processes को run कर सकता है, जैसे browser, music player और MS Word simultaneously चलना।

Multithreading का मतलब है एक single process या program के अंदर multiple threads run होना। इसमें एक application के अंदर ही कई tasks simultaneously execute हो सकते हैं। Multithreading multitasking का एक specific form माना जा सकता है जो same program के अंदर होता है।

Multitasking Example

Computer पर आप एक साथ YouTube चला रहे हैं, PDF पढ़ रहे हैं और file download कर रहे हैं। ये multiple applications/processes हैं, इसलिए यह multitasking है।

Multithreading Example

एक browser के अंदर एक thread webpage render कर रहा है, दूसरा video play कर रहा है और तीसरा file download कर रहा है। यह multithreading का example है।

Real Life Example:

Remember:

Advantages of Multithreading

Multithreading Java applications को fast, responsive और efficient बनाने में help करता है। Especially GUI applications, games, server applications, real-time systems और network applications में multithreading बहुत useful होता है।

Better CPU Utilization

Multithreading CPU को idle रहने से बचा सकता है। अगर एक thread input-output operation में wait कर रहा है, तो दूसरा thread CPU का use कर सकता है। इससे system resources का better use होता है।

Improved Responsiveness

GUI applications में अगर heavy task main thread पर run हो, तो application freeze हो सकती है। Multithreading से heavy task background में run होता है और user interface responsive रहता है।

Faster Task Execution

कुछ tasks को smaller parts में divide करके अलग-अलग threads में run किया जा सकता है। इससे total execution time reduce हो सकता है, especially multi-core processors पर।

Resource Sharing

Threads same process की memory share करते हैं। इससे data sharing processes की comparison में easy हो जाती है। लेकिन shared data के साथ synchronization जरूरी हो सकता है।

Useful for Server Applications

Server applications में multiple users की requests handle करनी होती हैं। हर user request को अलग thread से handle किया जा सकता है ताकि server multiple clients को simultaneously response दे सके।

Thread Life Cycle

Thread life cycle thread की different states को represent करता है। Java में thread object create होने से लेकर terminate होने तक कई states से गुजर सकता है। Thread scheduler और program logic decide करते हैं कि thread कब run होगा, कब wait करेगा और कब terminate होगा।

Image Placeholder: Thread Life Cycle Diagram

Main Thread States

State Meaning
New Thread object create हुआ है, लेकिन start नहीं हुआ।
Runnable Thread start हो चुका है और CPU मिलने का wait कर रहा है।
Running Thread currently execute हो रहा है।
Blocked/Waiting Thread किसी resource या condition का wait कर रहा है।
Timed Waiting Thread specific time के लिए wait/sleep कर रहा है।
Terminated Thread execution complete हो गया है।

New State

जब thread object create होता है लेकिन start() method call नहीं हुआ होता, तब thread New state में होता है।

Thread t = new Thread();

Runnable State

जब start() method call होता है, तो thread Runnable state में जाता है। इसका मतलब thread ready है, लेकिन CPU scheduler कब उसे run करेगा यह scheduler decide करेगा।

t.start();

Running State

जब thread को CPU मिलता है और उसका run() method execute होता है, तब thread Running state में होता है।

Waiting / Blocked State

Thread किसी resource lock, input-output operation या दूसरे thread के complete होने का wait कर सकता है। इस situation में thread waiting या blocked state में जा सकता है।

Timed Waiting State

जब thread sleep() या timed join जैसी method से specific time के लिए wait करता है, तो वह timed waiting state में होता है।

Thread.sleep(1000);

Terminated State

जब thread का run() method complete हो जाता है, तो thread terminated state में चला जाता है। Terminated thread को दुबारा start नहीं किया जा सकता।

Creating Threads by Extending Thread Class

Java में thread create करने का पहला तरीका है Thread class को extend करना। इसके लिए एक class Thread class को extend करती है और run() method को override करती है। Thread start करने के लिए object बनाकर start() method call किया जाता है।

Important बात यह है कि direct run() method call करने से new thread create नहीं होता। New thread create करने के लिए start() method call करना जरूरी है। start() internally run() method को new thread में execute करता है।

Image Placeholder: Thread Class Creation Diagram

Steps

  1. एक class बनाएं और Thread class को extend करें।
  2. run() method override करें।
  3. Class का object create करें।
  4. start() method call करें।

Example

class MyThread extends Thread {
    public void run() {
        System.out.println("Thread is running");
    }

    public static void main(String[] args) {
        MyThread t1 = new MyThread();

        t1.start();
    }
}
Output:
Thread is running

    }

    public static void main(String[] args) {
        MyThread t1 = new MyThread();

        t2.start();

Creating Threads by Implementing Runnable Interface

Java में thread create करने का दूसरा और commonly recommended तरीका है Runnable interface implement करना। इसमें class Runnable interface को implement करती है और run() method की body provide करती है। फिर उस class के object को Thread class के constructor में pass करके thread start किया जाता है।

Runnable interface approach better मानी जाती है क्योंकि Java में class केवल एक class extend कर सकती है। अगर कोई class already किसी other class को extend कर रही है, तो वह Thread class extend नहीं कर सकती। ऐसी situation में Runnable interface useful होता है।

Image Placeholder: Runnable Interface Thread Creation Diagram

Steps

  1. एक class बनाएं और Runnable interface implement करें।
  2. run() method override करें।
  3. Runnable class का object create करें।
  4. Runnable object को Thread constructor में pass करें।
  5. start() method call करें।

Example

class MyRunnable implements Runnable {
    public void run() {
        System.out.println("Thread is running using Runnable");
    }

    public static void main(String[] args) {
        MyRunnable obj = new MyRunnable();

        Thread t1 = new Thread(obj);

        t1.start();
    }
}
Output:
Thread is running using Runnable

Multiple Threads using Runnable

    public void run() {
        for (int i = 1; i <= 5; i++) {
            System.out.println(Thread.currentThread().getName() + " : " + i);
        }
    }

    public static void main(String[] args) {
        MyRunnable obj = new MyRunnable();

        Thread t1 = new Thread(obj);
        Thread t2 = new Thread(obj);

        t1.start();
        t2.start();
    }
}

Thread-1 : 1
Thread-0 : 2

Output order fixed नहीं होता।

Runnable with Custom Thread Name

class MyRunnable implements Runnable {
    public void run() {
        System.out.println("Running: " + Thread.currentThread().getName());
    }

    public static void main(String[] args) {
        MyRunnable obj = new MyRunnable();

        t2.start();
    }
}
Possible Output:
Running: Download Thread
Running: Music Thread

Why Runnable is Preferred

  • Java multiple class inheritance support नहीं करती, इसलिए Runnable flexible है।
  • Task और Thread object अलग रहते हैं।
  • Same Runnable object multiple threads को दिया जा सकता है।
  • Better object-oriented design possible होता है।
Remember:
Runnable interface में task define होता है, और Thread class उस task को अलग thread में run करती है।

Thread Class vs Runnable Interface

Java में thread create करने के लिए Thread class extend करना और Runnable interface implement करना दोनों possible हैं। लेकिन practical programming में Runnable approach ज्यादा flexible मानी जाती है। Thread class approach simple है, लेकिन अगर class already किसी दूसरी class को extend कर रही है, तो Thread class extend करना possible नहीं होगा।

Main thread important है क्योंकि यही program का starting point होता है। User-created threads भी main thread से ही create और start किए जाते हैं।

start() और run() methods multithreading में सबसे basic और important methods हैं। run() method thread का task define करता है, जबकि start() method new thread create करके उस task को execute करता है।

अगर programmer direct run() method call करता है, तो new thread create नहीं होता। वह normal method की तरह current thread में execute होता है। इसलिए actual multithreading के लिए start() method call करना जरूरी है।

Join method तब useful होता है जब किसी task का output दूसरे task के लिए जरूरी हो। For example, अगर calculation thread पहले complete होना चाहिए और फिर result print होना चाहिए, तो join use किया जा सकता है।

yield() Method

yield() method current running thread को temporarily pause करके scheduler को hint देता है कि same priority के other threads को chance दिया जा सकता है। यह guarantee नहीं देता कि दूसरा thread जरूर run होगा। Thread scheduler final decision लेता है।

Yield method static method है और इसे Thread.yield() के रूप में call किया जाता है। यह current thread को runnable state में वापस भेज सकता है ताकि scheduler other threads को consider कर सके।

Synchronization

Synchronization Java multithreading में एक technique है जिसका use shared resources को multiple threads द्वारा simultaneously access करने से protect करने के लिए किया जाता है। जब दो या more threads same data या same object को एक साथ modify करते हैं, तो inconsistent result आ सकता है। इस problem को control करने के लिए synchronization use होता है।

Java में synchronization lock या monitor concept पर based है। जब कोई thread synchronized method या synchronized block में enter करता है, तो वह object का lock acquire करता है। जब तक वह lock release नहीं करता, दूसरा thread उस synchronized section में enter नहीं कर सकता। इससे एक time पर only one thread critical section access करता है।

Image Placeholder: Synchronization Lock Concept Diagram

Need of Synchronization

  • Shared data को safe रखने के लिए।
  • Race condition avoid करने के लिए।
  • Data inconsistency prevent करने के लिए।
  • Thread-safe operations perform करने के लिए।
  • Banking, booking और transaction systems में correct result maintain करने के लिए।

Critical Section

Program का वह part जहाँ shared resource access या modify होता है, critical section कहलाता है। Critical section को synchronized बनाना important होता है ताकि multiple threads एक साथ उसे modify न कर सकें।

Example Idea

अगर दो users same bank account से एक साथ amount withdraw कर रहे हैं, तो balance update carefully होना चाहिए। अगर synchronization न हो, तो दोनों threads पुराने balance को read करके wrong transaction कर सकते हैं।

Real Life Example:
एक ATM machine में अगर same account से दो transactions एक साथ process हों, तो balance update synchronized होना चाहिए ताकि गलत balance न बने।
Remember:
Synchronization shared resource को one-thread-at-a-time access कराने की technique है।

Race Condition

Race condition वह problem है जिसमें multiple threads same shared data को एक साथ access और modify करते हैं, और final result thread execution order पर depend करने लगता है। इसका output unpredictable और गलत हो सकता है।

Race condition mostly तब होती है जब read-modify-write operation synchronized नहीं होता। For example, counter की value read करना, उसमें 1 add करना और फिर वापस store करना एक small operation जैसा लगता है, लेकिन internally यह multiple steps में होता है। अगर दो threads same time पर ये steps करें, तो update lost हो सकता है।

Image Placeholder: Race Condition Diagram

Race Condition Example

class Counter {
    int count = 0;

    void increment() {
        count++;
    }
}

class MyThread extends Thread {
    Counter c;

    MyThread(Counter c) {
        this.c = c;
    }

    public void run() {
        for (int i = 1; i <= 1000; i++) {
            c.increment();
        }
    }
}

class Main {
    public static void main(String[] args) throws Exception {
        Counter c = new Counter();

        MyThread t1 = new MyThread(c);
        MyThread t2 = new MyThread(c);

        t1.start();
        t2.start();

        t1.join();
        t2.join();

        System.out.println("Count: " + c.count);
    }
}
Possible Output:
Count: 1789
या कोई भी value 2000 से कम आ सकती है। Output fixed नहीं है।

Why Wrong Output Comes

  1. Thread-1 count की value read करता है।
  2. Thread-2 भी same old value read कर लेता है।
  3. दोनों value increment करते हैं।
  4. दोनों updated value वापस store करते हैं।
  5. एक update lost हो सकता है।

Solution Using synchronized

class Counter {
    int count = 0;

    synchronized void increment() {
        count++;
    }
}

अब एक time पर केवल एक thread increment method execute करेगा, इसलिए result correct आने की possibility strong हो जाती है।

Real Life Example:
Ticket booking system में अगर one seat बची है और two users simultaneously book करें, तो race condition से दोनों को same seat मिल सकती है। Synchronization इस problem को रोकता है।
Remember:
Race condition तब होती है जब shared data पर multiple threads बिना control के operation करते हैं।

Synchronized Method

Synchronized method वह method होता है जिसके declaration में synchronized keyword use किया जाता है। जब कोई thread synchronized method call करता है, तो वह current object का lock acquire करता है। जब तक method complete नहीं होता, दूसरा thread same object पर synchronized method execute नहीं कर सकता।

Synchronized method race condition avoid करने का easy तरीका है। अगर पूरा method critical section है, तो method को synchronized बनाना suitable होता है।

Image Placeholder: Synchronized Method Lock Diagram

Syntax

synchronized returnType methodName() {
    // critical section
}

Example

class Counter {
    int count = 0;

    synchronized void increment() {
        count++;
    }
}

class MyThread extends Thread {
    Counter c;

    MyThread(Counter c) {
        this.c = c;
    }

    public void run() {
        for (int i = 1; i <= 1000; i++) {
            c.increment();
        }
    }
}

class Main {
    public static void main(String[] args) throws Exception {
        Counter c = new Counter();

        MyThread t1 = new MyThread(c);
        MyThread t2 = new MyThread(c);

        t1.start();
        t2.start();

        t1.join();
        t2.join();

        System.out.println("Count: " + c.count);
    }
}
Output:
Count: 2000

How It Works

  1. Thread-1 synchronized method में enter करता है।
  2. Thread-1 object lock acquire करता है।
  3. Thread-2 same object पर wait करता है।
  4. Thread-1 method complete करके lock release करता है।
  5. Thread-2 lock acquire करके method execute करता है।

Advantages

  • Race condition avoid होती है।
  • Shared data safe रहता है।
  • Code simple और readable रहता है।
  • Critical method को protect करना easy होता है।

Limitation

अगर पूरा method synchronized है लेकिन critical section छोटा है, तो performance reduce हो सकती है क्योंकि method का non-critical part भी lock के अंदर execute होगा। ऐसी situation में synchronized block better हो सकता है।

Remember:
Synchronized method एक object पर एक time में only one thread को method execute करने देता है।

Synchronized Block

Synchronized block का use method के अंदर केवल specific critical section को synchronized बनाने के लिए किया जाता है। जब पूरा method synchronized करने की जरूरत न हो, तब synchronized block better approach होता है। इससे lock केवल उस code पर लगता है जहाँ shared resource access हो रहा है।

Synchronized block performance के लिए better हो सकता है क्योंकि यह complete method को lock नहीं करता, बल्कि only selected statements को lock करता है।

Image Placeholder: Synchronized Block Diagram

Syntax

synchronized (objectReference) {
    // critical section
}

Example

class Printer {
    void printDocument(String name) {
        System.out.println("Preparing document: " + name);

        synchronized (this) {
            for (int i = 1; i <= 3; i++) {
                System.out.println(name + " page " + i);
            }
        }

        System.out.println("Document completed: " + name);
    }
}

class MyThread extends Thread {
    Printer printer;
    String docName;

    MyThread(Printer printer, String docName) {
        this.printer = printer;
        this.docName = docName;
    }

    public void run() {
        printer.printDocument(docName);
    }
}

class Main {
    public static void main(String[] args) {
        Printer p = new Printer();

        MyThread t1 = new MyThread(p, "Java Notes");
        MyThread t2 = new MyThread(p, "Python Notes");

        t1.start();
        t2.start();
    }
}
Possible Output:
Preparing document lines intermix हो सकती हैं, लेकिन synchronized block के अंदर pages एक document के complete print होंगे।

Synchronized Method vs Synchronized Block

Basis Synchronized Method Synchronized Block
Lock Area पूरा method lock होता है। Only selected code block lock होता है।
Performance अगर method बड़ा है, तो slower हो सकता है। Better performance दे सकता है।
Use जब पूरा method critical हो। जब method का छोटा part critical हो।
Control Less control More control

Important Point

Synchronized block में lock object carefully choose करना चाहिए। अगर threads same lock object use नहीं करते, तो synchronization effective नहीं होगा।

Remember:
Synchronized block केवल selected critical section को lock करता है, इसलिए यह method synchronization से ज्यादा controlled होता है।

Static Synchronization

Static synchronization static methods को synchronize करने के लिए use होती है। Static synchronized method object lock नहीं, बल्कि class-level lock use करता है। इसका मतलब है कि class के static synchronized method को एक time पर only one thread execute कर सकता है, even अगर different objects use हो रहे हों।

Normal synchronized method object lock use करता है। अगर two different objects हैं, तो दो threads same synchronized method को different objects पर simultaneously execute कर सकते हैं। लेकिन static synchronized method class lock use करता है, इसलिए lock पूरे class level पर apply होता है।

Static Synchronized Method

class Display {
    static synchronized void printTable(int n) {
        for (int i = 1; i <= 5; i++) {
            System.out.println(n * i);

            try {
                Thread.sleep(300);

                System.out.println(e);
            }

class MyThread2 extends Thread {

Inter-thread Communication

Inter-thread communication का मतलब है threads का आपस में communicate करना। Java में wait(), notify() और notifyAll() methods inter-thread communication के लिए use होते हैं। ये methods Object class में defined हैं, इसलिए हर Java object इन्हें use कर सकता है।

Inter-thread communication तब useful होती है जब एक thread को दूसरे thread द्वारा कोई condition complete होने तक wait करना हो। For example, producer-consumer problem में consumer तब तक wait करता है जब तक producer data produce न कर दे।

Image Placeholder: wait notify notifyAll Diagram

Methods

Method Use
wait() Current thread को wait state में भेजता है और lock release करता है।
notify() Waiting threads में से one thread को wake up करता है।
notifyAll() All waiting threads को wake up करता है।

Important Rule

wait(), notify() और notifyAll() methods को synchronized context के अंदर call करना चाहिए। Otherwise IllegalMonitorStateException आ सकती है।

Simple Example

class Shared {
    synchronized void waitMethod() {
        try {
            System.out.println("Thread waiting");
            wait();
            System.out.println("Thread resumed");
        } catch (InterruptedException e) {
            System.out.println(e);
        }
    }

    synchronized void notifyMethod() {
        System.out.println("Notifying thread");
        notify();
    }
}

class Main {
    public static void main(String[] args) throws Exception {
        Shared obj = new Shared();

        Thread t1 = new Thread(() -> obj.waitMethod());
        Thread t2 = new Thread(() -> obj.notifyMethod());

        t1.start();

        Thread.sleep(1000);

        t2.start();
    }
}
Possible Output:
Thread waiting
Notifying thread
Thread resumed

wait() vs sleep()

Basis wait() sleep()
Class Object class Thread class
Lock Lock release करता है। Lock release नहीं करता।
Use Inter-thread communication Thread pause करना
Call Context Synchronized block/method में call करना चाहिए। कहीं भी call हो सकता है।
Remember:
wait lock release करता है, sleep lock release नहीं करता।

Thread Safety

Thread safety का मतलब है कि program या class multiple threads द्वारा use होने पर भी correct और consistent result दे। अगर multiple threads shared data को access कर रहे हैं और data corrupt नहीं होता, तो code thread-safe कहलाता है।

Thread safety achieve करने के लिए synchronization, immutable objects, atomic operations, thread-safe collections और proper locking techniques use की जाती हैं।

Image Placeholder: Thread Safety Concept Diagram

Thread Unsafe Example

class Counter {
    int count = 0;

    void increment() {
        count++;
    }
}

यह code thread-safe नहीं है क्योंकि multiple threads count को simultaneously update कर सकते हैं।

Thread Safe Example

class Counter {
    int count = 0;

    synchronized void increment() {
        count++;
    }
}

Ways to Achieve Thread Safety

Technique Explanation
Synchronization Critical section को lock करके one thread at a time access देता है।
Immutable Objects Object state change नहीं होती, इसलिए sharing safe होती है।
Atomic Classes Atomic operations thread-safe तरीके से perform होते हैं।
Thread-safe Collections Special collections concurrent access handle करती हैं।
Local Variables Method local variables हर thread के stack में separate होती हैं।

Important Points

  • Shared mutable data thread safety risk create करता है।
  • Immutable data generally safe होता है।
  • Synchronization correct use करें, unnecessary use performance reduce कर सकता है।
  • Thread safety live projects में बहुत important है।
Real Life Example:
Bank balance update, seat booking, stock quantity update और wallet transaction thread-safe होने चाहिए।
Remember:
Thread-safe code multiple threads के साथ भी correct result देता है।

Deadlock

Deadlock multithreading की serious problem है जिसमें two or more threads हमेशा के लिए एक-दूसरे के lock release करने का wait करते रहते हैं। इस situation में program stuck हो सकता है और threads आगे execute नहीं कर पाते।

Deadlock mostly तब होता है जब multiple threads multiple locks को different order में acquire करते हैं। Thread-1 Lock-A hold करके Lock-B का wait करे और Thread-2 Lock-B hold करके Lock-A का wait करे, तो deadlock बन सकता है।

Image Placeholder: Deadlock Circular Waiting Diagram

Deadlock Example

class DeadlockExample {
    public static void main(String[] args) {
        final String resource1 = "Printer";
        final String resource2 = "Scanner";

        Thread t1 = new Thread() {
            public void run() {
                synchronized (resource1) {
                    System.out.println("Thread 1 locked Printer");

                    try {
                        Thread.sleep(100);
                    } catch (Exception e) {
                        System.out.println(e);
                    }

                    synchronized (resource2) {
                        System.out.println("Thread 1 locked Scanner");
                    }
                }
            }
        };

        Thread t2 = new Thread() {
            public void run() {
                synchronized (resource2) {
                    System.out.println("Thread 2 locked Scanner");

                    try {
                        Thread.sleep(100);
                    } catch (Exception e) {
                        System.out.println(e);
                    }

                    synchronized (resource1) {
                        System.out.println("Thread 2 locked Printer");
                    }
                }
            }
        };

        t1.start();
        t2.start();
    }
}
Possible Output:
Thread 1 locked Printer
Thread 2 locked Scanner
Program stuck हो सकता है।

Conditions for Deadlock

Condition Meaning
Mutual Exclusion Resource एक time पर only one thread use कर सकता है।
Hold and Wait Thread एक resource hold करके दूसरे का wait कर रहा है।
No Preemption Resource forcibly thread से छीना नहीं जा सकता।
Circular Wait Threads circular chain में एक-दूसरे का wait करते हैं।

How to Avoid Deadlock

  • Locks हमेशा same order में acquire करें।
  • Nested locks avoid करें जहाँ possible हो।
  • Lock holding time कम रखें।
  • Unnecessary synchronization avoid करें।
  • Timeout-based locking techniques use करें।
Real Life Example:
दो लोग एक-दूसरे की bike key लेकर खड़े हों और दोनों अपनी key वापस मिलने तक दूसरे को key न दें, तो दोनों stuck हो जाएंगे। यही deadlock जैसा है।
Remember:
Deadlock में threads एक-दूसरे के lock release होने का wait करते रहते हैं और program stuck हो सकता है।

Livelock and Starvation

Livelock और starvation multithreading की extra important problems हैं। ये deadlock जैसी famous problems नहीं हैं, लेकिन practical thread scheduling और resource sharing में समझना useful है।

Image Placeholder: Livelock and Starvation Diagram

Livelock

Livelock में threads active तो रहते हैं, लेकिन useful progress नहीं कर पाते। Threads बार-बार अपनी state change करते रहते हैं, लेकिन task complete नहीं होता। Deadlock में threads stuck हो जाते हैं, जबकि livelock में threads move करते हुए भी आगे नहीं बढ़ते।

Starvation

Starvation में किसी thread को लंबे समय तक required resource या CPU time नहीं मिल पाता क्योंकि other threads repeatedly resources use करते रहते हैं। Low priority thread starvation का शिकार हो सकता है अगर high priority threads constantly CPU use कर रहे हों।

Comparison

Problem Meaning Thread State
Deadlock Threads एक-दूसरे का wait करते हुए stuck हो जाते हैं। No progress, blocked
Livelock Threads active हैं लेकिन useful progress नहीं। Active but no progress
Starvation Thread को resource/CPU time बहुत देर तक नहीं मिलता। Waiting for chance

How to Reduce Starvation

  • Thread priorities carefully use करें।
  • Fair locking mechanisms use करें।
  • Long-running locks avoid करें।
  • Resource allocation balanced रखें।
Remember:
Deadlock में threads stuck होते हैं, livelock में active होते हुए भी progress नहीं करते, और starvation में thread को chance नहीं मिलता।

Best Practices

Multithreading powerful है, लेकिन गलत use करने पर race condition, deadlock, data inconsistency और debugging problems आ सकती हैं। इसलिए professional coding में multithreading best practices follow करना जरूरी है।

Image Placeholder: Multithreading Best Practices Diagram

Important Best Practices

  • Shared mutable data को carefully synchronize करें।
  • Unnecessary synchronization avoid करें क्योंकि performance reduce हो सकती है।
  • Locks को minimum time तक hold करें।
  • Nested locks avoid करें जहाँ possible हो।
  • Deadlock avoid करने के लिए locks same order में acquire करें।
  • Thread names meaningful रखें ताकि debugging easy हो।
  • Sleep को logic control के लिए overuse न करें।
  • Runnable interface या modern concurrency tools prefer करें।
  • Exceptions को thread के अंदर properly handle करें।
  • Thread-safe collections और atomic classes use करें जहाँ suitable हो।

Bad Practice

synchronized void fullMethod() {
    // long non-critical code
    // small critical code
    // more long non-critical code
}

अगर critical part छोटा है, तो पूरा method synchronize करना performance reduce कर सकता है।

Better Practice

void method() {
    // non-critical code

    synchronized (this) {
        // only critical code
    }

    // non-critical code
}
