Data Model

Introduction to Data Model

Data Model database में data की structure, relationships, constraints और operations को represent करने का formal तरीका है। यह बताता है कि data कैसे organize होगा, different records एक-दूसरे से कैसे जुड़े होंगे और users data पर कौन-कौन से operations perform कर सकेंगे।

Image Placeholder: Data Model Overview

Need of Data Model

  • Database structure को clearly define करना।
  • Entities और relationships identify करना।
  • Database design को simple बनाना।
  • Data redundancy कम करना।
  • Developers और users के बीच common understanding बनाना।
Remember:
Data model database का blueprint होता है।

Meaning and Characteristics of Data Model

Data model rules, concepts और symbols का collection होता है जिसकी सहायता से real-world information को database structure में represent किया जाता है।

Characteristics

  • Data structure define करता है।
  • Relationships specify करता है।
  • Constraints enforce करता है।
  • Data manipulation operations support करता है।
  • Logical और physical design के बीच bridge बनाता है।

Major Types of Data Models

Model Structure Main Use
Hierarchical Model Tree structure Parent-child data
Network Model Graph structure Many-to-many links
Relational Model Tables General database systems
E-R Model Entities and relationships Conceptual database design

Hierarchical Data Model

Hierarchical Model data को tree structure में organize करता है। इसमें एक root record होता है और हर child का केवल एक parent होता है।

Image Placeholder: Hierarchical Tree Structure

Example

College
 ├── Department
 │    ├── Teacher
 │    └── Student
 └── Library

Advantages

  • Simple tree structure।
  • Fast navigation in fixed relationships।
  • Parent-child data के लिए useful।
  • Security hierarchy implement करना आसान।

Disadvantages

  • Many-to-many relationship difficult।
  • Structure rigid होती है।
  • Data duplication हो सकती है।
  • Changes करना complex हो सकता है।

Network Data Model

Network Model records को graph structure में organize करता है। इसमें एक child के multiple parents हो सकते हैं और many-to-many relationships represent की जा सकती हैं।

Image Placeholder: Network Model Graph

Example

एक student multiple courses join कर सकता है और एक course में multiple students हो सकते हैं।

Advantages

  • Many-to-many relationship support।
  • Flexible connections।
  • Complex relationships efficiently represent करता है।
  • Fast navigational access।

Disadvantages

  • Design complex हो सकता है।
  • Maintenance difficult।
  • Structure-dependent programming।
  • Casual users के लिए समझना कठिन।

Introduction to E-R Model

E-R Model का full form Entity-Relationship Model है। यह database design का conceptual model है जिसमें real-world objects को entities और उनके connections को relationships के रूप में represent किया जाता है।

Image Placeholder: Basic Entity Relationship Model

Main Components

  • Entity
  • Entity Set
  • Attribute
  • Relationship
  • Relationship Set
  • Keys
  • Constraints

Advantages

  • Database design visually clear होता है।
  • Real-world system easy to represent होता है।
  • Developers और users दोनों समझ सकते हैं।
  • Relational schema बनाने में help करता है।

Disadvantages

  • Very large systems में diagram complex हो सकता है।
  • Physical implementation details show नहीं करता।
  • Some advanced constraints represent करना difficult हो सकता है।

Super Key

Super Key one or more attributes का set होता है जो entity को uniquely identify कर सकता है। इसमें unnecessary attributes भी included हो सकते हैं।

Example

Student table में Student_ID और Student_ID + Name दोनों super keys हो सकते हैं।

Candidate Key

Candidate Key minimal super key होती है। इसमें कोई unnecessary attribute नहीं होता।

Example

Student_ID और Email दोनों candidate keys हो सकते हैं, यदि दोनों unique हैं।

Primary Key

Primary Key candidate keys में से selected key होती है जो entity को uniquely identify करती है। इसकी value unique और non-null होती है।

Example

Student_ID को primary key select किया जा सकता है।

Unique Key

Unique Key attribute की values को unique बनाती है। कुछ DBMS में unique key null value allow कर सकती है, जबकि primary key null नहीं होती।

Basis Primary Key Unique Key
Uniqueness Required Required
Null Not allowed DBMS-dependent
Count per Table One Multiple possible

Converting ER Model to Relational Tables

Basic Rules

  • Strong entity को table में convert करें।
  • Attributes को columns बनाएं।
  • Primary key select करें।
  • One-to-many relationship में foreign key add करें।
  • Many-to-many relationship के लिए separate table बनाएं।
  • Weak entity table में owner key include करें।
Student(Student_ID, Name)
Course(Course_ID, Title)
Enrollment(Student_ID, Course_ID)

Common ER Design Mistakes

  • Entity और attribute में confusion।
  • Primary key missing।
  • Wrong cardinality।
  • Many-to-many relationship को direct table में रखना।
  • Weak entity dependency ignore करना।
  • Derived attribute को unnecessarily store करना।
  • Duplicate entities बनाना।
