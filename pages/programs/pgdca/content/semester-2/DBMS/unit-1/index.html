1. Basic Concepts of Database System

आज के समय में लगभग हर organization large amount of data generate और use करती है। College में students, courses, attendance और marks का data, bank में customers, accounts और transactions का data तथा e-commerce में products, customers और orders का data maintain किया जाता है। यदि यह data व्यवस्थित तरीके से manage न किया जाए, तो information को ढूँढना, update करना और सुरक्षित रखना कठिन हो जाता है।

Database related data का एक organized collection है। Database का उद्देश्य data को इस प्रकार व्यवस्थित रखना है कि आवश्यक information को आसानी से store, retrieve, update और manage किया जा सके।

DBMS (Database Management System) एक software system है जो users और database के बीच interface provide करता है। यह database को define, create, store, manipulate, retrieve और control करने में सहायता करता है। Modern DBMS का मुख्य उद्देश्य large volumes of data को efficiently manage करना और users/applications को controlled access देना है। citeturn0search13turn0search9

Database System क्या होता है?

Database system केवल database तक सीमित नहीं होता। इसमें database, DBMS software, applications, users और supporting hardware/software environment मिलकर काम करते हैं। जब user कोई query या operation करता है, DBMS उस request को process करके database से appropriate result देता है।

Users / Applications → DBMS → Database ← Result / Response ←

Database के Basic Terms

Term Detailed Meaning
Data Raw facts or values, जैसे Student Name, Roll Number, Age और Marks।
Information Processed और meaningful data जिसे decision making में उपयोग किया जा सकता है।
Database Related data का structured और organized collection।
DBMS Database को define, store, retrieve, update और control करने वाला software।
Table Relational database में rows और columns में data रखने की logical structure।
Record / Tuple Table की एक complete row जो किसी entity instance की information रखती है।
Field / Attribute किसी record की एक property, जैसे Name, Age या RollNo।
Database Schema Database की structure/blueprint जिसमें tables, attributes और relationships का description होता है।
Exam Definition: DBMS is a software system that provides an interface for defining, creating, maintaining and controlling access to a database.

2. Need and Importance of DBMS

File-based systems में अलग-अलग applications अपनी files maintain कर सकती हैं। जैसे college में admission department की एक file, examination department की दूसरी file और accounts department की तीसरी file हो सकती है। जैसे-जैसे organization बड़ी होती है, duplicate data, inconsistent data, difficult sharing और security problems बढ़ सकती हैं।

DBMS का database approach इन समस्याओं को centralized और systematic तरीके से handle करने का प्रयास करता है। DBMS data sharing, controlled access, data abstraction, backup/recovery और data independence जैसी facilities provide करता है।

Major Reasons for Using DBMS

  1. Controlled Data Storage: Data को organized database structure में manage किया जा सकता है।
  2. Data Sharing: Authorized multiple users एक ही database से information access कर सकते हैं।
  3. Reduced Redundancy: Unnecessary duplicate data को reduce करने में सहायता मिलती है।
  4. Improved Consistency: Centralized control के कारण conflicting copies की समस्या कम की जा सकती है।
  5. Security: User permissions और authorization के द्वारा access control किया जा सकता है।
  6. Backup and Recovery: System failure के बाद data recovery mechanisms उपयोग किए जा सकते हैं।
  7. Data Independence: Storage या logical structure में कुछ changes applications को प्रभावित किए बिना किए जा सकते हैं।
  8. Concurrent Access: कई users के simultaneous operations को manage किया जा सकता है।

3. Advantages of DBMS over File Processing System

Traditional file processing में application programs data files के format और storage details पर अधिक dependent हो सकते हैं। एक ही information अलग-अलग files में duplicate हो सकती है। DBMS database को centrally manage करके इन समस्याओं को कम करने के लिए mechanisms provide करता है।

Basis File Processing System DBMS
Data Redundancy Same data multiple files में repeat हो सकता है। Centralized database और design techniques redundancy को reduce कर सकती हैं।
Data Consistency Multiple copies update न होने पर inconsistent values हो सकती हैं। Controlled updates consistency maintain करने में मदद करते हैं।
Data Sharing Different applications के बीच sharing कठिन हो सकती है। Authorized users/applications database share कर सकते हैं।
Security Security अक्सर individual applications/files पर dependent होती है। Centralized authorization और access control facilities मिलती हैं।
Data Independence Programs और file structures में strong dependence हो सकती है। Schema levels के कारण data independence support होती है।
Backup & Recovery System/application dependent। DBMS recovery and backup mechanisms support कर सकता है।
Concurrent Access Multiple users के simultaneous updates manage करना difficult हो सकता है। Concurrency control mechanisms available होते हैं।
Querying हर task के लिए अलग application/program की आवश्यकता हो सकती है। Database query languages के माध्यम से flexible retrieval possible है।
Exam Point: DBMS के प्रमुख advantages हैं: reduced redundancy, improved consistency, data sharing, security, backup/recovery, concurrency control और data independence.

4. Data Abstraction

Database systems internally complex होते हैं। Data को disk पर किस location पर store किया गया है, कौन-सा index use हुआ है या कौन-से blocks involved हैं—इन details की सामान्य user को आवश्यकता नहीं होती। Data Abstraction unnecessary और irrelevant implementation details को hide करके user को केवल required information provide करने की concept है। citeturn0search1turn0search5

Objectives of Data Abstraction

  • Database की complexity को कम करना।
  • Users को simple logical view provide करना।
  • Storage details को hide करना।
  • Different users को अलग-अलग views देना।
  • Data independence प्राप्त करने में सहायता करना।

Three Levels of Data Abstraction

1. Physical / Internal Level

यह lowest level है। यह बताता है कि data वास्तव में secondary storage पर कैसे organized और stored है। File organization, indexes, access paths, blocks आदि physical details इस level से संबंधित हो सकते हैं।

2. Logical / Conceptual Level

यह बताता है कि database में कौन-सा data stored है और entities, attributes तथा relationships किस प्रकार organized हैं। User को physical storage details जानने की आवश्यकता नहीं होती।

3. View / External Level

यह highest level है। अलग-अलग users/applications को उनके requirement के अनुसार database का relevant subset दिखाया जाता है।

External / View Level ↓ Conceptual / Logical Level ↓ Internal / Physical Level ↓ Physical Storage
Example: Bank customer को केवल account balance और transaction history दिखाई जा सकती है। DBMS के internal storage blocks, indexes या file locations customer को दिखाई नहीं देते।

5. Database Languages

Database languages specialized languages/commands हैं जिनका उपयोग database के structure को define करने, data को manipulate करने, permissions control करने और transactions manage करने के लिए किया जाता है। GeeksforGeeks के DBMS/SQL references में DDL, DML, DCL और TCL को प्रमुख categories के रूप में explain किया गया है। citeturn0search3turn0search11

1. DDL — Data Definition Language

DDL का उपयोग database schema या structure को define और modify करने के लिए किया जाता है। Tables, views, indexes जैसे schema objects create या modify किए जा सकते हैं।

Command Use
CREATE New database object/table आदि create करना।
ALTER Existing structure में modification करना।
DROP Database object को remove करना।
TRUNCATE Table के records remove करना जबकि table structure बना रहता है।

2. DML — Data Manipulation Language

DML का उपयोग stored data को insert, update, delete और manipulate करने के लिए किया जाता है। Modern SQL usage में SELECT को data retrieval के लिए अलग DQL category में भी बताया जाता है। citeturn0search13turn0search7

Command Use
INSERT New records add करना।
UPDATE Existing records modify करना।
DELETE Records remove करना।
SELECT Data retrieve करना; कई syllabi में इसे DQL कहा जाता है।

3. DCL — Data Control Language

DCL database access permissions और privileges control करने के लिए use होती है।

  • GRANT: User को privileges देना।
  • REVOKE: Previously granted privileges हटाना।

4. TCL — Transaction Control Language

TCL database transactions को control करने के लिए use होती है। COMMIT changes को save करता है, जबकि ROLLBACK transaction changes को previous committed state की ओर वापस ले जाने में सहायता करता है। citeturn0search3turn0search7

Example

CREATE TABLE Student ( RollNo INT, Name VARCHAR(50), Marks INT ); INSERT INTO Student VALUES (101, 'Amit', 78); SELECT * FROM Student; UPDATE Student SET Marks = 82 WHERE RollNo = 101; COMMIT;

6. Data Independence

Data Independence DBMS की वह property है जिसमें database schema के एक level पर changes करने पर higher level schema या application programs पर unwanted effect न पड़े। इसका उद्देश्य database को flexible और maintainable बनाना है। citeturn0search0turn0search4

Why Data Independence is Important?

  • Application programs को बार-बार modify करने की आवश्यकता कम होती है।
  • Database को performance और storage requirements के अनुसार reorganize किया जा सकता है।
  • System maintenance आसान होता है।
  • Long-term database evolution आसान होती है।

1. Physical Data Independence

Physical data independence का अर्थ है internal/physical level में changes करने की ability बिना conceptual/logical schema को प्रभावित किए। उदाहरण के लिए file organization method बदलना, नया index add करना या storage device बदलना logical structure को change किए बिना किया जा सकता है। citeturn0search0turn0search1

2. Logical Data Independence

Logical data independence का अर्थ है conceptual schema में changes करने की ability बिना external views और application programs को अनावश्यक रूप से प्रभावित किए। उदाहरण के लिए existing table में नया attribute add करना, यदि existing user view को उस attribute की आवश्यकता नहीं है। citeturn0search0turn0search4

Feature Physical Independence Logical Independence
Change Physical storage/internal structure Logical/conceptual structure
Should not affect Conceptual level External views/applications
Example Index/file organization बदलना New attribute add करना

7. Components of a DBMS

DBMS एक single simple program नहीं है; इसमें कई subsystems मिलकर database operations perform करते हैं। Exact internal implementation DBMS product के अनुसार अलग हो सकती है, लेकिन conceptually query processing, storage management, transaction/recovery और catalog/authorization जैसी responsibilities महत्वपूर्ण होती हैं।

Major Components

Component Detailed Function
Query Processor User queries को parse, validate, optimize और execute करने में सहायता करता है।
Storage Manager Disk storage, files, indexes, buffers और data access को manage करता है।
Transaction Manager Transactions के execution और concurrent operations को coordinate करता है।
Recovery Manager System failures के बाद database को consistent state में recover करने में सहायता करता है।
Authorization Manager Users की permissions और access rights को control करने में सहायता करता है।
Integrity Manager Database constraints और integrity rules को maintain करने में सहायता करता है।
Buffer Manager Disk और main memory के बीच data pages/blocks के movement को manage करता है।
Data Dictionary / Catalog Tables, attributes, constraints, indexes आदि के बारे में metadata रखता है।

Database Administrator (DBA) की भूमिका

DBA database system की administration, security, authorization, backup/recovery, performance monitoring और schema-related management जैसी activities में महत्वपूर्ण भूमिका निभाता है।

8. Overall Structure of a DBMS

DBMS structure को broadly user/application layer, query processing layer, storage management layer और actual database storage के रूप में समझा जा सकता है।

Users / Application Programs ↓ SQL / Query ↓ Query Processor (Parsing + Optimization + Execution) ↓ Storage Manager ↓ ┌──────────┼───────────┐ ↓ ↓ ↓ Data Files Indexes Catalog ↓ Physical Storage

Working Explanation

  1. User application या SQL interface के माध्यम से request देता है।
  2. Query processor query की syntax और meaning check करता है।
  3. Query optimization process suitable execution strategy choose करने में मदद करती है।
  4. Storage manager required records/pages को storage से access करता है।
  5. Database operation perform होता है।
  6. Result वापस application/user को दिया जाता है।
DBMS architecture का exact internal design DBMS implementation पर depend करता है, लेकिन exam में Query Processor, Storage Manager, Database, Catalog और transaction/recovery responsibilities को explain करना useful है।

9. Three Views of Data

एक ही database को अलग-अलग users अलग तरीके से देख सकते हैं। DBMS तीन-level schema approach के द्वारा user-specific views और complete logical/physical representation को अलग रखता है। ANSI-SPARC architecture में External, Conceptual और Internal levels describe किए जाते हैं। citeturn0search6turn0search1

External View

External view सबसे user-oriented level है। इसमें केवल वही entities, attributes और relationships दिखाई जाती हैं जो किसी particular user/application के लिए relevant हैं। एक database की कई external views हो सकती हैं।

Example: Student portal में student को Name, RollNo, Course और Marks दिख सकते हैं; accounts staff को Fees और Payment Status का view दिया जा सकता है।

Conceptual View

Conceptual view organization/community level पर पूरे database का logical representation देता है। इसमें यह बताया जाता है कि कौन-सा data stored है और entities के बीच relationships क्या हैं। यह physical storage considerations से independent logical structure provide करता है। citeturn0search6

Internal View

Internal view lowest level है। यह database के physical implementation को describe करता है—data storage, file organization, indexes और access paths जैसी implementation details इस level से संबंधित हो सकती हैं। citeturn0search6

View Level Main Focus Example
External Highest User-specific information Student portal view
Conceptual Middle Complete logical database Student, Course, Fee entities & relationships
Internal Lowest Physical storage Files, indexes, storage blocks

10. Three-Level Architecture of DBMS

Three-level architecture database system में user views को logical database structure और physical storage से अलग करती है। इसका प्रमुख उद्देश्य abstraction और data independence support करना है। citeturn0search6turn0search0

EXTERNAL LEVEL
View 1 • View 2 • View 3 • ... • View n

↓

CONCEPTUAL LEVEL
Complete Logical Database Schema

↓

INTERNAL LEVEL
Physical Database Storage

External Level

यह highest abstraction level है। अलग-अलग users को database का customized view दिया जाता है। Security और simplicity के लिए user को unnecessary information hide की जा सकती है।

Conceptual Level

यह middle level है और पूरे database की logical structure describe करता है। इसमें entities, attributes, relationships और constraints का logical description शामिल हो सकता है। यह level physical storage details से independent होता है।

Internal Level

यह lowest level है और actual physical storage representation से संबंधित है। DBMS यहाँ storage structures और access mechanisms के माध्यम से data को efficiently store/retrieve करता है।

Advantages of Three-Level Architecture

  1. Different users को customized views मिलते हैं।
  2. Physical storage details users से hidden रहती हैं।
  3. Data abstraction improve होती है।
  4. Physical और logical data independence support होती है।
  5. Database maintenance और evolution comparatively आसान होती है।

11. Schema and Instance

Schema database की overall logical structure या blueprint है। यह बताता है कि database में कौन-सी tables/entities, attributes और relationships defined हैं। Schema relatively stable होता है और database design को represent करता है।

Instance किसी particular time पर database में stored actual data का current state है। जब records insert, update या delete होते हैं, database instance change हो सकता है, जबकि schema जरूरी नहीं कि हर data change पर बदले।

Schema Instance
Database structure/blueprint Particular time पर actual stored data
Comparatively stable Frequently change हो सकता है
Tables, attributes, relationships describe करता है उन tables में current records represent करता है

12. Client-Server Architecture

Client-server architecture में client application server से services या data के लिए request करती है और server request process करके response देता है। DBMS में client side पर user interface/application हो सकता है और server side पर database management services तथा database मौजूद हो सकते हैं। GeeksforGeeks के DBMS architecture reference के अनुसार two-tier architecture basic client-server model की तरह काम करता है, जहाँ client application database server से directly communicate कर सकती है। citeturn0search12turn0search10

Two-Tier Client-Server Model

Client / User Interface │ │ Request / SQL ↓ Database Server / DBMS │ ↓ Database │ └──── Response → Client

Client

Client वह system/application है जो user interaction handle करता है और server को database requests भेजता है। Desktop application, web application का client part या other software client की भूमिका निभा सकता है।

Server

Server database services provide करता है। यह queries execute कर सकता है, transactions manage कर सकता है, security rules apply कर सकता है और database से result return कर सकता है।

Working

  1. User client application में request enter करता है।
  2. Client request को server/database service तक भेजता है।
  3. Server request को process करता है।
  4. DBMS required data retrieve/update करता है।
  5. Server result client को return करता है।
  6. Client result user को display करता है।

Advantages

  • Centralized data management।
  • Multiple clients database access कर सकते हैं।
  • Database security और authorization centralized हो सकते हैं।
  • Data sharing आसान होती है।
  • Backup और maintenance centralized हो सकते हैं।

Three-Tier Extension

Large web applications में client और database के बीच एक application/middle tier हो सकता है। इस architecture में presentation tier, application/business logic tier और database tier अलग होते हैं। इससे scalability, maintainability और security improve हो सकती है। citeturn0search2turn0search8

Presentation / Client Tier ↓ Application / Business Logic Tier ↓ Database / Data Management Tier

Three abstraction levels से related। Physical और Logical types होते हैं।

External Conceptual Internal

Highest Middle Lowest

Two-Tier vs Three-Tier

Two-Tier Three-Tier
